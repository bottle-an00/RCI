# miniGIT 클라우드(웹 진단 앱) 기능개발 요청서

*Development Request — Cloud / Web Diagnostic App*

- 문서번호: MINIGIT-REQ-CLOUD-001
- 버전: 0.1
- 작성일: 2026-07-27
- 분류: 학습용 (내부)
- 요청 주체: RC카/RCI 개발 담당
- 수신 대상: 클라우드(웹 진단 앱) 개발 담당
- 관련 문서: [진단 통신 사양서 v1.1](../사양서/README.md), [RCI 기능명세서](../기능명세서/RCI_기능명세서_ver1.0.md), [RC카 기능명세서](../기능명세서/RC카_기능명세서_ver0.2.md)

> 본 문서는 클라우드(웹 진단 앱) 담당자가 개발에 착수할 수 있도록 **알아야 할 모든 인터페이스·프로토콜·책임 범위**를 정리한 요청서다.
> 웹 진단 앱은 실제 제품의 **GDS-SMART 앱을 대체**하며, MQTT를 통해 RCI(게이트웨이)와 통신한다.

## 1. 배경 및 전체 구조

```
[웹 진단 앱(클라우드)] ──MQTT──▶ [RCI(RSP4)] ──OBD/CAN──▶ [RC카(RSP5)=ECU]
      GDS-SMART 대체              VCI 장치 대체              차량/ECU 대체
      └────────── MQTT 응답 ◀──── 번역/중계 ◀──── CAN 응답 ◀──────┘
```

- 웹앱 ↔ RCI: **MQTT** (블루투스 대체)
- RCI ↔ RC카: CAN + UDS 유사 바이트 프레임
- **RCI는 순수 바이트 중계기**: MQTT의 raw 바이트를 CAN으로 전달하고, CAN 응답 바이트를 MQTT로 되돌릴 뿐, 진단 값의 의미를 해석하지 않는다.

### 1.1 매우 중요 — 역할 분담

| 작업 | 담당 | 설명 |
|---|---|---|
| UI/화면 | **클라우드** | 진단 기능 버튼·입력·결과 표시 |
| **UI 조작 → UDS 요청 바이트 조립** | **클라우드** | 예: "초음파 읽기" 버튼 → `"22 01 01"` |
| MQTT 발행/구독 | **클라우드** | §3 토픽/페이로드 |
| MQTT ↔ CAN 중계, 필러/ISO-TP, 타임아웃 | RCI | 클라우드는 신경 쓸 필요 없음 |
| **응답 raw 바이트 → 물리값 디코딩** | **클라우드** | 예: `00 EB` → 235 mm |
| **NRC 바이트 → 이름/메시지 매핑** | **클라우드** | 예: `31` → requestOutOfRange |
| ECU 처리(센서/액추에이터/DTC) | RC카 | — |

> 즉 클라우드는 **UDS 프로토콜(요청 조립 + 응답 디코딩)의 주체**다. 본 문서 §5의 프로토콜 표가 그 사양이다.

## 3. MQTT 인터페이스 계약 (Contract)

RCI 기능명세서 §4와 **동일 스키마**를 사용해야 통신이 성립한다.

### 3.1 브로커

| 항목 | 값 |
|---|---|
| 위치 | **클라우드 호스팅** (클라우드 담당이 구축·운영) |
| RCI 접속 | RCI가 이 브로커에 클라이언트로 접속 → **접속 정보를 RCI 담당에게 전달 필요** |
| 포트 | 1883 (기본) — TLS/인증 사용 시 해당 정보 공유 |
| 프로토콜 | MQTT 3.1.1 이상 |

> 학습용이라 보안(TLS/인증)은 기본 미사용이나, 클라우드 브로커가 요구하면 자격증명·인증서를 RCI 담당에게 제공한다.

### 3.2 토픽

| 토픽 | 방향 | 발행자 | QoS | Retained |
|---|---|---|---|---|
| `minigit/req/rccar` | 명령 | **웹앱** | 1 | N |
| `minigit/resp/rccar` | 응답 | RCI | 1 | N |
| `minigit/error/rccar` | 에러 | RCI | 1 | N |
| `minigit/status/rci` | RCI 생존 | RCI | 1 | **Y (+LWT)** |

- 웹앱: `minigit/req/rccar` 발행 + `minigit/resp/rccar`·`minigit/error/rccar`·`minigit/status/rci` 구독.

### 3.3 페이로드 (JSON)

```jsonc
// 요청 (웹앱 발행)
{ "id": "r-0001", "raw": "22 01 01", "timeout_ms": 1000 }
//  id        : 요청-응답 상관용 고유 문자열 (웹앱 생성)
//  raw       : UDS 유효 페이로드 hex (필러 제외). RCI가 필러/ISO-TP 처리
//  timeout_ms: 선택(기본 1000). 리프로그래밍 등 장시간 작업은 상향

// 긍정 응답 (RCI 발행)
{ "id": "r-0001", "type": "positive", "raw": "62 01 01 00 EB" }

// 부정 응답
{ "id": "r-0001", "type": "negative", "raw": "7F 22 31", "nrc": "31" }

// 에러
{ "id": "r-0001", "type": "error", "reason": "timeout", "message": "차량 무응답" }
//  reason ∈ { "timeout", "can_tx_failed", "bus_off" }

// RCI 상태 (retained)
{ "state": "online" }   // LWT(RCI 비정상 종료 시): { "state": "offline" }
```

### 3.4 표기 규칙 (엄수)

- **hex 표기**: 대문자, 바이트 공백 구분, `0x` 접두어 없음. 예 `"62 01 01 00 EB"`, `nrc`=`"31"`.
- **`id`**: 웹앱이 생성, RCI가 그대로 에코. 동시에 하나의 요청만 진행(단일 세션) 권장.
- **`type` 판별**: raw 첫 바이트가 `7F`면 부정, 아니면 긍정. (웹앱이 raw 해석)
- **8바이트 초과**: 웹앱은 UDS 페이로드를 그대로 `raw`로 보내면 되고, CAN 분할(ISO-TP)은 RCI가 처리한다. **웹앱은 ISO-TP를 구현할 필요 없음.** (단, 리프로그래밍 대량 데이터는 §6.3처럼 UDS 블록 단위로 나눠 보낸다.)

## 4. 요청 조립 / 응답 디코딩 규칙

### 4.1 요청 조립 (UI → raw)

- **긍정 요청 포맷**: `[SID] [파라미터...]`
- 예: 센서 읽기 → `[0x22] [DID_H] [DID_L]` → `"22 01 01"`

### 4.2 응답 디코딩 (raw → 표시값)

- **긍정 응답**: 첫 바이트 = `요청 SID + 0x40`. 이후 데이터는 §5 인코딩표대로 해석.
  - 예: `62 01 01 00 EB` → DID 0x0101(초음파), 값 `0x00EB`=235 → **235 mm**
  - 예: `62 01 03 00 FA` → DID 0x0103(온도), `0x00FA`=250 → **25.0℃**
- **부정 응답**: `7F [SID] [NRC]` → §5.7 NRC표로 이름/메시지 매핑.

## 5. UDS 프로토콜 사양 (클라우드가 구현할 대상)

값은 [진단 통신 사양서 v1.1](../사양서/README.md) 확정본과 동일하다. 아래는 웹앱 구현에 필요한 형태로 재정리한 것이다.

### 5.1 서비스(SID) 목록

| SID | 서비스 | 긍정 응답 SID | 용도 |
|---|---|---|---|
| 0x10 | DiagnosticSessionControl | 0x50 | 세션 시작/전환 |
| 0x11 | ECUReset | 0x51 | 제어기 리셋 |
| 0x14 | ClearDiagnosticInformation | 0x54 | DTC 소거 |
| 0x19 | ReadDTCInformation | 0x59 | DTC 읽기 |
| 0x22 | ReadDataByIdentifier | 0x62 | 센서/사양 읽기 |
| 0x27 | SecurityAccess | 0x67 | 보안 접근 |
| 0x2E | WriteDataByIdentifier | 0x6E | 데이터 쓰기 |
| 0x2F | InputOutputControlByIdentifier | 0x6F | 액추에이터 강제 구동 |
| 0x31 | RoutineControl | 0x71 | 루틴 제어 |
| 0x34 | RequestDownload | 0x74 | 다운로드 요청 |
| 0x36 | TransferData | 0x76 | 데이터 전송 |
| 0x37 | RequestTransferExit | 0x77 | 전송 종료 |
| 0x3E | TesterPresent | 0x7E | 세션 유지 |

### 5.2 세션 제어 (0x10)

| SF | 세션 | 용도 |
|---|---|---|
| 0x01 | defaultSession | 기본 |
| 0x02 | programmingSession | 리프로그래밍 (보안 필요) |
| 0x03 | extendedDiagnosticSession | 쓰기/강제구동 |

```
요청: 10 03      응답: 50 03 00 32 01 F4   (P2=50ms, P2*=5000ms)
```

- 확장/프로그래밍 세션 유지: **웹앱이 `3E 00`을 2초 이내 주기로 발행**해야 한다(미발행 시 ECU가 default로 복귀). 응답 `7E 00`.

### 5.3 센서 읽기 (0x22, DID 0x01xx) — 계기판 데이터 소스

| DID | 항목 | 응답 길이 | 타입 | 디코딩 |
|---|---|---|---|---|
| 0x0101 | 초음파 거리 | 2B | uint16 | mm |
| 0x0102 | 배터리 전압 | 2B | uint16 | mV |
| 0x0103 | 온도 | 2B | int16 | 값/10 = ℃ (250→25.0) |
| 0x0104 | 습도 | 2B | uint16 | 값/10 = %RH |
| 0x0105 | 조도 | 2B | uint16 | lux |
| 0x0106 | 서보 각도(와이퍼) | 1B | uint8 | deg (0~180) |
| 0x0107 | LED 상태 | 1B | bitfield | b0=적, b1=황, b2=백 (1=ON) |
| 0x0108 | 부저 상태 | 1B | uint8 | 0=OFF, 1=ON |

```
요청: 22 01 01    응답: 62 01 01 00 EB     # 235 mm
```

### 5.4 사양/식별 정보 (0x22, DID 0xF1xx)

| DID | 항목 | 타입 | 디코딩 |
|---|---|---|---|
| 0xF199 | SW 업데이트 날짜 | 3B BCD | YYMMDD (26 07 23 → 2026-07-23) |
| 0xF1A0 | 제어기 CAN ID | 2B uint16 | 11bit ID |
| 0xF195 | SW 버전 | 4B ASCII | "V1.2" |
| 0xF18C | 시리얼 번호 | 가변 ASCII | 식별자 |

### 5.5 액추에이터 강제 구동 (0x2F, DID 0x02xx)

포맷: `2F [DID_H] [DID_L] [IOControlParameter] [제어데이터...]`
IOControlParameter: `0x03`=강제 조정(shortTermAdjustment), `0x00`=제어권 반환(returnControlToECU)

| DID | 액추에이터 | 제어 데이터 |
|---|---|---|
| 0x0201 | DC모터 (전/후진 구동) | 1B 방향(0정지/1전진/2후진) + 1B 속도(0~100%) |
| 0x0202 | 서보모터 (와이퍼) | 1B 각도(0~180) |
| 0x0203 | LED | 1B bitfield (b0=적,b1=황,b2=백) |
| 0x0204 | 부저 | 1B(0OFF/1ON) 또는 2B 주파수(Hz) |
| 0x0205 | MP3 가상사운드 | 1B 트랙ID(0정지) + 1B 볼륨(0~100%) |

> **조향(좌/우)은 제공하지 않는다** — DC모터는 전/후진 구동만.

```
요청: 2F 02 01 03 01 50    응답: 6F 02 01 03 01 50   # 모터 전진, 속도 80%
요청: 2F 02 01 00          응답: 6F 02 01 00          # 제어권 반환(정지)
```

### 5.6 보안(0x27) / 쓰기(0x2E) / 루틴(0x31)

- **보안 접근**: `27 01`(Seed 요청) → `67 01 11 22 33 44`(Seed=0x11223344 고정) → `27 02 55 66 77 88`(Key=0x55667788 고정) → `67 02`(성공). Key 3회 실패 시 잠금.
- **쓰기(0x2E)**: 확장 세션 + 보안 완료 후, 사양 정보(0xF1xx) 대상. 예 `2E F1 A0 01 8A` → `6E F1 A0`.
- **루틴(0x31)**: `31 [SF] [RID]` — SF 0x01 start/0x02 stop/0x03 결과. RID 0xFF00 메모리 소거, 0xFF01 체크섬 검증.

### 5.7 DTC (0x19 / 0x14)

DTC = 3B 코드 + 1B 상태(0x08=confirmed).

| DTC 코드 | 의미 |
|---|---|
| 0x900001 | CAN 버스 단선 |
| 0xC10101 | 초음파 센서 이상 |
| 0xC10201 | 온습도 센서 이상 |
| 0xC10301 | 조도 센서 이상 |
| 0xC10401 | 카메라 출력 이상 |

```
요청: 19 02 08     응답: 59 02 90 00 01 08 ...   # 상태마스크 0x08로 읽기
요청: 14 FF FF FF  응답: 54                        # 전체 소거
```

### 5.8 NRC (부정 응답 코드) — 이름 매핑용

`7F [SID] [NRC]` 형식. 주요 NRC:

| NRC | 이름 | 의미 |
|---|---|---|
| 0x10 | generalReject | 일반 거부 |
| 0x11 | serviceNotSupported | 미지원 서비스 |
| 0x12 | subFunctionNotSupported | 미지원 서브펑션 |
| 0x13 | incorrectMessageLengthOrInvalidFormat | 길이/포맷 오류 |
| 0x22 | conditionsNotCorrect | 조건 불충족 |
| 0x24 | requestSequenceError | 요청 순서 오류 |
| 0x31 | requestOutOfRange | 요청 범위 밖(잘못된 DID 등) |
| 0x33 | securityAccessDenied | 보안 접근 거부 |
| 0x35 | invalidKey | 잘못된 키 |
| 0x36 | exceededNumberOfAttempts | 키 시도 횟수 초과 |
| 0x37 | requiredTimeDelayNotExpired | 지연시간 미경과 |
| 0x70 | uploadDownloadNotAccepted | 다운로드 거부 |
| 0x72 | generalProgrammingFailure | 프로그래밍 실패 |
| 0x73 | wrongBlockSequenceCounter | 블록 시퀀스 오류 |
| 0x78 | responsePending | 처리 중(RCI 내부 처리, 웹앱은 응답/타임아웃만 수신) |
| 0x7E | subFunctionNotSupportedInActiveSession | 현재 세션 미지원 SF |
| 0x7F | serviceNotSupportedInActiveSession | 현재 세션 미지원 서비스 |
| 0x93 | voltageTooLow | 전압 부족(리프로그래밍 차단 등) |

> 전체 목록은 사양서 7장 참조. 웹앱은 최소한 위 항목을 사용자 메시지로 표시할 것을 권장.

## 6. 시나리오 흐름 (웹앱 구현 참고)

### 6.1 센서 읽기 (계기판)

```
[UI] 초음파 버튼 → raw "22 01 01" 생성
 → publish req {"id":"r-0001","raw":"22 01 01"}
 ← resp {"id":"r-0001","type":"positive","raw":"62 01 01 00 EB"}
[UI] 00 EB = 235 → "235 mm" 표시
```

### 6.2 보안 후 쓰기

```
10 03  → 50 03 ...           확장 세션
27 01  → 67 01 11 22 33 44   Seed = 0x11223344
27 02 55 66 77 88 → 67 02    Key = 0x55667788, 인증 성공
2E F1 A0 01 8A → 6E F1 A0    CAN ID 쓰기
```

### 6.3 리프로그래밍 (다크모드 전환 트리거)

전체 순서:
```
27(보안) → 10 02(프로그래밍 세션) → 31 01 FF00(소거)
 → 34(다운로드 요청) → 36(데이터 전송, 반복) → 37(종료)
 → 31 01 FF01(검증) → 11 01(리셋)
```
- **10 02 진입 시점부터 UI 다크모드 전환**(CR10), 11 01 리셋/정상 종료 시 해제.
- 대량 데이터(0x36)는 웹앱이 UDS 블록 단위(`36 [BSC] [data...]`)로 나눠 순차 발행하고, 각 블록의 `76 [BSC]` 응답 확인 후 다음 블록 발행. 진행률 표시 권장.
- `timeout_ms`를 소거/검증 단계에 맞게 상향.

## 7. UI 기능 상세 요청 (사양서 10장)

### 7.1 웹 네비 계기판 (CR9)

- 0x22 센서를 **주기 폴링**(예 200~500ms)하여 실시간 계기판 표시: 속도(모터 상태)·거리(초음파)·배터리·온습도·조도 등.
- 폴링 주기·대상 DID는 웹앱 재량. 과도한 폴링은 지양(단일 세션·직렬 처리 고려).

### 7.2 리프로그래밍 다크모드 (CR10)

- 프로그래밍 세션(`10 02`) 진입 ~ 종료(리셋/`10 01`) 구간 동안 UI를 다크모드로 전환.

## 8. 제약 및 참고
