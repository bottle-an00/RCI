## 1. 범위 (Scope)

교육생(PC/태블릿 브라우저)이 진단통신을 **읽고 · 직접 써보고 · 눈으로 확인하는** 웹 교육
플랫폼. GDS-SMART 진단기를 대체하는 화면이며, MQTT로 RCI(게이트웨이)와 왕복한다.

담당하는 것:
- 이론 교육자료 뷰어, 퀴즈(응시·채점·결과 서버 기록), 실습 준비 안내
- UDS 요청 조립(자동 시퀀스 / 사람이 직접 작성), 응답 raw → 물리값·NRC 디코딩
- 세션 유지(0x3E) 주기 발행과 그 수명 관리
- 통신 로그 / 디버그 로그 표시, 3D 모델로 강제구동 결과 시각화

담당하지 않는 것:
- MQTT ↔ CAN/DoIP 중계, ISO-TP 필러·타임아웃 (RCI)
- 센서·액추에이터 실제 처리 (RC카 / UR3)
- 사용자 계정·권한 체계 (없음. 학습자 식별은 퀴즈 제출 시 자기신고)

## 2. 시스템 구성

```
 [브라우저]  ── MQTT over WebSocket (ws:8080/mqtt) ──┐
   화면·디코딩·시퀀스 실행                            │
      │ HTTP(8123)                                   ├─▶ [MQTT 브로커] ─── [RCI] ─── [RC카 / UR3]
      ▼                                              │
 [FastAPI 서버]  ── paho-mqtt (tcp:1883) ────────────┘
   Jinja2 서버 렌더링 + /api/* 검증 경로
```

**MQTT 경로가 두 개인 것이 이 앱의 핵심 구조**다.

| 경로 | 주체 | 용도 |
|---|---|---|
| 브라우저 직결 (`static/js/rci-live.js`) | 브라우저 ↔ 브로커, WebSocket | 실습 화면의 실제 왕복. 응답은 서버를 거치지 않는다 |
| 서버측 브리지 (`mqtt_bridge.py`) | FastAPI ↔ 브로커, TCP | `curl` 한 줄로 브라우저 없이 연동 확인 (`/api/*`) |

두 경로는 **병존**하며 같은 계약(`minigit/...`)을 쓴다. 응답이 브라우저로 직접 오기 때문에
"단계 통과 여부 · 연결 여부"를 서버는 알 수 없다 — 이 한 줄이 §5·§6 설계의 근거다.

### 2.1 소프트웨어 스택

| 계층 | 선택 | 비고 |
|---|---|---|
| 웹 서버 | FastAPI + Uvicorn (기본 8123 포트) | `cloud/dev.bat` 로 기동 |
| 템플릿 | Jinja2 서버 렌더링 | SPA 아님. 항목 선택 = 페이지 리로드 |
| 프런트 | 순수 JS (빌드 없음), 20개 모듈 | `static/js/*.js`, 각 파일 상단에 설계 의도 주석 |
| 벤더 | `mqtt.min.js` · `model-viewer.min.js` · `mermaid.min.js` | CDN 아닌 **로컬 동봉** (오프라인 교육장 대응) |
| md 변환 | `markdown` (서버) + mermaid (브라우저) | 다이어그램만 브라우저 렌더 |
| MQTT | `paho-mqtt` (서버) / `mqtt.js` (브라우저) | |
| 저장소 | 파일 기반 (`data/quiz.json`, `content/`, `TEST_RESULT/`) | DB 없음 |

## 3. 정보구조 (화면 계층)

target-first 3단계. 대상 슬러그가 경로 접두사로 하위 전 화면에 물려 내려간다.

```
/                        Step1  대상 선택 (진단 모사 차량 / UR Robot)
/{target}                Step2  컨텐츠 그리드 (학습·준비 / 진단·실습)
/{target}/{content}      Step3  콘텐츠 화면 (view 로 템플릿 디스패치)
/search                  통합 검색 (플레이스홀더)
```

|---|---|---|---|---|
| `rc-car` | 진단 모사 차량 | `rccar` | CAN | `hyundai_ioniq_5_lowpoly.glb` (RC카 모델 준비 전 대역) |
| `ur-robot` | UR Robot | `urrobot` | DoIP | `UR_Robot.glb` |

## 4. 학습·준비 기능

### 4.1 이론 교육 (`theory_content.py`, `theory.html`)

- 자료 원천 = `content/theory/**/*.md` **폴더 스캔**. 자료 추가 = md 파일 하나 떨어뜨리기
  (하드코딩 목록 없음). 현재 9개 과목 폴더 · 42개 문서.
- frontmatter: `title` / `difficulty`(기초·기본·심화) / `order`. 정렬은 난이도 → order → 제목.
- 좌측은 '큰 주제 ▸ 소제목' 2단 그룹 트리, 우측은 **소제목(h1/h2) 단위로 끊은 한 페이지**만
  변환해 표시(`?doc=…&page=N`). 페이지 이동은 주소 이동 — mermaid가 보이는 요소에서만
  제대로 그려지기 때문에 감춰 두고 JS로 갈아 끼우지 않는다.
- 과목의 첫 자료는 **표지 페이지**(만화 컷 + 학습 시작 CTA)를 먼저 띄운다. 만화를 마지막
  컷까지 넘겨야 CTA가 활성화된다.
- 영상(mp4 등)을 참조하는 자료는 목록·본문에서 제외(`has_video`).
- 이미지·표·인라인 SVG는 서버가 그대로 통과, ```mermaid 블록만 브라우저가 렌더.

### 4.2 실습 준비 (`PREP_GUIDES`, `detail.html`)

장비 체결뿐 아니라 **실습 전에 읽는 것 전반**(이론 교육·퀴즈 화면 사용법 포함). 항목은
데이터(dict)로 정의하고 템플릿은 구조만 그린다. 본문의 `{label}` `{transport}`는 선택한
대상에 따라 치환된다. 각 항목은 해당 탭으로 바로 보내는 액션 버튼을 가질 수 있다.

### 4.3 퀴즈 (`quiz.js`, `learner-gate.js`, `data/quiz.json`)

| 항목 | 내용 |
|---|---|
| 문항 원천 | 담당자 원문 `.doc` → `tools/import_quiz.py` → `data/quiz.json` |
| 규모 | 10개 주제(디지털/UDS 기초·심화/DoIP 기초·심화의 사전·사후) · 총 160문항 |
| 스키마 | `{id, text, code?, choices[4], answer(정답 **인덱스**), explain?}` |
| 진입 게이트 | 소속·이름·직급 필수 입력. 스크림·Esc로 닫을 수 없음. 같은 탭이면 재입력 없음 |
| 보기 순서 | 응시할 때마다 섞는다 (원문은 정답이 A에 몰려 있어 찍기 방지). `quiz.json` 원문은 불변 |
| 진행·채점 | 전부 클라이언트. 서버 왕복 없음(주제 전환만 리로드). 제출 후 문항별 해설 표시 |
| 결과 제출 | 제출 시 1회 `POST /api/quiz-result` |

### 4.4 퀴즈 결과 기록 (서버)

- 저장 위치: **서버 PC**의 `Codes/Cloud/TEST_RESULT/YYYY-MM-DD.json` (날짜별 배열에 append).
- 기록 필드: 퀴즈 · 소속 · 이름 · 직급 · 제출시각 · 소요시간_초 · 점수 · 제출IP.
- **제출시각·제출IP는 클라이언트 값이 아니라 서버가 찍는다** (응시자 조작 방지, 자리 추적).
- 동시 제출 대비: 파일 갱신 전체를 `threading.Lock`으로 직렬화(엔드포인트가 동기 함수라
  스레드풀 병렬 실행 → 잠그지 않으면 한쪽 기록이 사라진다).
- 쓰기는 임시 파일 → `replace` (중간에 죽어도 반쪽 JSON이 남지 않음).
- 손상된 날짜 파일은 `*.corrupt-<시각>.json`으로 옮기고 새로 시작 — 한 건 때문에 그날
  이후 모든 제출이 실패하는 쪽이 훨씬 나쁘다.
- 확인: `GET /api/quiz-result[?date=YYYY-MM-DD]`.

## 5. 진단·실습 — 자동 시퀀스 (진단 / 강제구동 / ECU)

### 5.1 책임 분담

| 항목 | 담당 | 근거 |
|---|---|---|
| 단계 **순서** 정의 | 서버 `auto_sequence()` → `<script id="seq-plan">` JSON | 프로토콜 절차라 고정 |
| **실행·페이싱·실패 정책** | 브라우저 `auto-sequence.js` | 응답을 브라우저가 직접 받는다 |
| 단계 설명 패널 | 서버가 전 단계 분을 미리 렌더 → `seq-brief.js`가 토글 | 연결 없이도 읽으며 공부 가능 |

단계 필드: `title / raw / expect / note / kind(ka_start·ka_stop·seed·key) / critical / topic`.

**한 번 누르면 한 단계**다. 12단계가 자동으로 흘러가면 로그만 쌓이고 '지금 무엇을 왜
하는지'는 지나가 버린다 — 설명을 읽고 납득한 뒤 다음을 누르는 리듬이라야 순서가 남는다.

### 5.2 시퀀스 구성

| 카테고리 | 세션 | 보안접근 | 본 동작 |
|---|---|---|---|
| 진단 | 확장(03) | 없음 | `22 {DID}` 센서 읽기 → `19 02 08` 확정 고장코드 조회 |
| 강제구동 | 확장(03) | 있음(27 01/02) | `2F {DID} 03 {값}` 구동 → `2F {DID} 00` **제어권 반환** |
| ECU 업그레이드 | 프로그래밍(02) | 있음 | `34` 다운로드 요청 → `36` 블록 3회 → `37` 종료 → `31 01 FF 01` 검증 → 3E 중지 → `11 01` 리셋 |

공통 앞머리 = 세션 오픈 + **세션 유지(3E) 반복 발행 시작**, 공통 마무리 = 3E 중지 + 세션 종료.
보안 Key는 서버가 만들 수 없다(Seed를 받아야 알 수 있으므로) — 브라우저가 Seed 각 바이트에
`+0x44`(학습용 알고리즘)를 더해 만든다. Seed 길이는 rc-car 2B / ur-robot 4B.

세부 항목(트리 잎) → DID 매핑:

| 대상 | 진단 | 강제구동 |
|---|---|---|
| rc-car | CDS 조도 `01 05` · 초음파 `01 01` · 온도 `01 03` | 모터 `02 01` · 서보 `02 02` · 와이퍼 `02 03` · LED `02 07` · 부저 `02 08` · MP3 `02 09` |
| ur-robot | 조인트각 `01 01` · 전압 `01 0A` · 진동 `01 11` | 전체 `02 01` · 베이스 `02 04` · 숄더 `02 05` · 엘보우 `02 06` · 손목2 `02 07` |

### 5.3 세션 유지(0x3E)의 수명 — `rci-live.js`, `practice-scope.js`

세션 유지는 웹앱 책임(요청서 CR5)이고, 이 앱에서는 **화면에 머무는 동안만 유효한 상태**로
다룬다.

- 주기 2초(허용 0.5~5초). 5초를 넘기면 ECU가 스스로 기본 세션으로 되돌아간다.
- 연속 무응답 3회면 중단하고 사유를 로그에 남긴다.
- 발행은 `sessionStorage`에 적혀 페이지를 넘어가도 이어지지만, **소유 범위(`ka_scope`)**가
  있다: 같은 실습의 단계 이동은 유지, 경로가 바뀌면(다른 실습·이론으로 이동) 끊는다.
- 진행 체크(localStorage)도 같은 규칙으로 지운다 — 그러지 않으면 앞 교육생이 밟아 둔
  체크가 열려 있고 3E가 계속 나가는 상태로 다음 사람이 시작하게 된다.

### 5.4 첫 진입 커버 (만화)

진단·강제구동·ECU는 세부 항목을 고르기 전 첫 진입 시 실행 화면 대신 **만화 커버**를
띄운다. 마지막 컷까지 넘겨야 '실습하러 가기'가 활성화된다. 메시지 작성은 이미 [배경·이론
↔ 작성기] 구조가 있어 제외.

       └CAN ID  │  └ PCI(ISO-TP 길이)
                └ DLC
출력  층별 색 분해 + 검증 결과 + (UDS만) 전송
```

- 검증이 교육 가치다. 자주 틀리는 것을 짚어준다 — PCI에 DLC(8)를 적음 / 필러 방향
  반대(요청 0x55, 응답 0xAA) / 8바이트 초과인데 PCI를 `0L`로 둠.
- **전송되는 것은 UDS raw뿐**이다. CAN 프레이밍은 RCI 몫이라 프레임 층은 화면에만 존재한다.
- 실습 코스 4종(트리): 센서 리딩(4단계) / DTC 조회·소거(6단계) / 강제 구동(5단계) /
  데이터 쓰기(6단계). 각 코스는 세션 오픈 → 세션 유지 → (보안) → 본 동작 → 세션 종료.
- **순차 진행 강제**: 코스마다 첫 미통과 단계까지만 열리고 뒤는 잠긴다. 통과 조건은
  응답 SID = 요청 SID + 0x40. 통과 판정은 브라우저(localStorage), 서버는 '다음 단계 주소'만
  내려준다.
- 화면 전환: [배경·이론] ↔ [메시지 작성]을 같은 페이지 안에서 갈아 끼운다(`stage-switch.js`)
  — 페이지를 옮기면 3E 발행이 끊기고 작성 중이던 입력이 날아가기 때문. 기본은 배경·이론.
- 하단 참고 자료(읽기 전용): 프레임 층 설명, NRC 표, 부정 응답 형식, 단계별 예시 프레임.

## 7. 통신 표시

### 7.1 로그 패널 (`_log.html`, `log-tab.js`)

**통신 로그**(오간 메시지·디코딩 결과)와 **디버그 로그**(접속·모드·경고)를 탭 전환이 아니라
**좌우 나란히** 표시한다. 탭이면 한쪽을 보는 동안 다른 쪽에서 무슨 일이 있었는지 놓친다.

### 7.2 응답 디코딩 (`rci-live.js`) — 요청서 CR4

게이트웨이는 raw만 준다. 물리값·NRC 해석은 이 앱 몫이다.

| 대상 | 디코딩 |
|---|---|
| 0x62 읽기 응답 | DID별 물리값(조인트 6축 각도·속도·온도·전류, TCP 자세, 조도·거리·온습도, 전압/전류) |
| 로봇 모드·안전 모드·프로그램 상태 | 코드 → 이름(NORMAL / PROTECTIVE_STOP / PLAYING …) |
| 0x59 DTC | 3바이트 코드 → `P/C/B/U`+숫자, 1바이트 상태 비트 → 한글 상태 |
| 0x6F 강제구동 | 제어 옵션(0x00 제어권 반환 / 0x03 단기 조정) |
| 0x7F 부정 응답 | NRC → 이름·설명 (0x78 '처리 중'은 최종 응답을 기다림) |
| 식별 정보 | BCD 날짜 · ASCII 문자열 |

### 7.3 3D 모델 뷰 (`_model3d.html`, `view3d-tab.js`)

만화 자리와 **같은 패널을 나눠 쓰는 탭**이다(만화 ↔ 3D). 강제구동이 실제로 시작되면
(0x6F 응답의 제어 옵션 0x03) `view3d:show-model` 이벤트로 **3D 탭으로 자동 전환**해
눈으로 반응을 확인하게 한다.

DID → 표현 매핑(`DRIVE_EFFECTS`), 시작=옵션 0x03 / 종료=옵션 0x00:

| 표현 | 동작 | 적용 |
|---|---|---|
| `light` | 발광 머티리얼(`M_Emission`) 3회 점멸 후 소등 | RC카 전조등 `0207` |
| `loop` | 구워진 클립을 제어 반환까지 반복 재생 | RC카 모터 `WheelSpin` · 서보(조향) `SteerFront` · 와이퍼 `WiperSweep` |
| `motion` | 클립 1회 재생 | UR 전체 `UR3Track` · 베이스/숄더/엘보우/손목2 (`UR3Track` 채널을 관절별로 분리) |
| `pulse` | 모델로 표현 못 하는 동작을 패널 배지로 표시(+오디오) | RC카 부저(경적음 `horn.wav`) · MP3 |

모델은 `<model-viewer>`로 렌더한다. 유휴 자동회전은 제거 — 강제구동 동작과 구분이 안 됐다.

> **제약**: model-viewer는 머티리얼만 공개하고 노드 변환은 손댈 수 없다. 그래서 지금은
> "구워진 클립 재생"이며, DID 0x0101의 **실제 관절 각도로 자세를 직접 만드는 것**은
> three.js 직접 렌더로 옮겨야 가능하다 (§10).

## 8. 전송 모드 (R&D)

`rci-live.js`가 세 모드를 갈라 준다. `window.RCI.send()` 뒤에서 처리되므로 상위 화면 코드는
모드를 모른다.

| 모드 | 경로 | 용도 |
|---|---|---|
| `mock` 목업 | 브라우저 안에서 응답 생성 (`mock-rci.js`) | 브로커 없이 화면 작업 |
| `mqtt` MQTT 목업 | 브로커 경유 · PC의 `mock_rci.py`가 응답 | 계약·왕복 확인 |
| `rci` RCI(MQTT) | 브로커 경유 · PC 목업은 침묵, 실물 RCI만 응답 | 실물 연동 |

- 뒤 두 모드는 **전송 경로가 완전히 같다.** 다른 것은 `minigit/control/mock/{device}`로
  보내는 억제 선언(retained) 하나뿐이다.
- 모드는 **device마다 따로** 기억한다(localStorage) — UR은 실물 RCI가 있고 RC카는 없어서,
  한 값을 공유하면 UR을 실물 모드로 돌린 순간 RC카 화면이 아무도 응답하지 않는 상태가 된다.
- `mock-rci.js`는 `Codes/board/mock_rci.py`의 `build_response()` 이식판이다. **두 파일은 같은
  표(DID·Seed/Key·DTC)를 들고 있어 한쪽을 고치면 다른 쪽도 고쳐야 한다.**
- 전환 UI(상단 토글)는 현재 `hidden`으로 감춰 두었다. 되살리려면 `_subhead.html`의 `hidden`
  속성만 지우면 된다.

## 9. 서버 인터페이스

### 9.1 HTTP API

| 메서드 · 경로 | 설명 | 실패 |
|---|---|---|
| `GET /api/health` | 브로커 연결 상태 + 마지막 RCI 생존 상태(retained) | — |
| `GET /api/status/{device}` | 해당 device의 최신 status | 404 미수신 |
| `POST /api/diag/{device}/request` | UDS 요청 발행 후 같은 id의 응답 대기·반환 (`{raw, timeout_ms}`) | 400 표기오류 / 504 타임아웃 / 503 미연결 |
| `POST /api/quiz-result` | 퀴즈 결과 1건 기록 | 500 저장 실패 |
| `GET /api/quiz-result?date=` | 저장된 결과 되읽기 | 400 날짜 형식 |
| `GET /api/events` | 오가는 MQTT 메시지를 SSE 로 스트리밍 (`curl -N`으로 관찰) | — |

> 라우트 순서 주의: `/api/*`는 캐치올 `/{target_id}`보다 **먼저** 선언되어야 한다(Starlette은
> 선언 순서대로 첫 일치를 쓴다).

### 9.2 MQTT (계약은 `MQTT_Interface_Contract.md`)

```
요청  minigit/req/{device}         {id, raw, timeout_ms}                웹 → RCI  QoS1
응답  minigit/resp/{device}        {id, type, raw, nrc?}                RCI → 웹  QoS1
에러  minigit/error/{device}       {id, type:"error", reason, message}  RCI → 웹  QoS1
상태  minigit/status/rci-{ur|rc}   {state, robot}                       retained + LWT
제어  minigit/control/mock/{device} {suppress}                          웹 → 목업  retained
```

서버 브리지는 paho 콜백에서 값만 뽑아 `loop.call_soon_threadsafe()`로 이벤트 루프에 넘긴다
(Future/Queue를 루프 밖 스레드에서 만지면 동시 요청에서 깨진다).

### 9.3 설정 (환경변수)

| 변수 | 용도 |
|---|---|
| `RCI_BROKER_HOST` / `PORT` / `USERNAME` / `PASSWORD` / TLS | 서버측 브리지의 브로커 접속 |
| `RCI_WS_URL` | 브라우저가 붙을 ws URL 전체를 직접 지정 |
| `RCI_BROKER_WS_HOST` / `_WS_PORT` / `_WS_PATH` / `_WS_TLS` | 브라우저용 ws URL 조립 (기본 8080·`/mqtt`) |

브라우저용 호스트가 없으면 **루프백은 걸러내고** 빈 값을 내려 클라이언트가 현재 접속
호스트로 폴백한다 — 서버의 localhost와 태블릿의 localhost는 다른 기계이기 때문이다.
브로커 자격증명은 **의도적으로 HTML에 내려보내지 않는다**(누구나 볼 수 있다).

## 10. 요청서 대비 현황 · 미구현

| 요청서 | 상태 | 비고 |
|---|---|---|
| CR1 브로커 호스팅 | 구현 | 서버·브라우저 양 경로 접속. 학습용이라 TLS/인증 기본 미사용 |
| CR2 진단 UI | 구현 | 진단·강제구동·ECU·메시지 작성 |
| CR3 요청 조립 | 구현 | 자동 시퀀스(서버 정의) + 직접 작성(검증형) |
| CR4 응답 디코딩 | 구현 | §7.2 |
| CR5 세션 관리·3E | 구현 | 소유 범위·무응답 중단 포함 (§5.3) |
| CR6 보안 접근 | 구현 | Seed → `+0x44` Key (학습용 알고리즘) |
| CR7 리프로그래밍 | 구현 | 8단계 시퀀스, 더미 블록 3개 |
| CR8 상태/에러 처리 | 구현 | LWT 기반 연결 표시 + NRC/타임아웃 표시 |
| CR9 웹 네비 계기판 | **미구현** | 실시간 센서 계기판 UI 없음. 현재는 로그의 디코딩 값으로 대체 |
| CR10 리프로그래밍 다크모드 | **미구현** | 프로그래밍 세션 진입 시 UI 전환 없음 |
| — 통합 검색 | **플레이스홀더** | `/search` 화면만 존재 |

기타 알려진 제약:
- RC카 3D 모델이 아직 없어 아이오닉5 저폴리 모델을 대역으로 사용 중.
- UR 그리퍼 전용 클립이 없어 `0203`이 `UR3Track`을 재사용한다.
- 발광 머티리얼 이름(`M_Emission`)이 RC카 모델에 고정되어 있어 UR 조명 연동은 불가
  (조명 DID 0x0207이 RC카에만 있어 현재는 문제되지 않음).
- 사용자 인증 없음. 퀴즈 결과의 신원은 자기신고 + 제출IP.
