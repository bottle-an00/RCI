# (4) 물리 계층 및 연결 환경

## **4. 물리 계층 및 연결 환경**

#### 4.1 차량용 이더넷 물리 계층

**진단에 사용되는 물리 계층 규격**

| 규격 | 속도 | 배선 | 주요 용도 |
| --- | --- | --- | --- |
| **100BASE-TX** | 100 Mbps | UTP 2쌍 (4선) | 외부 진단기 연결 구간 |
| **100BASE-T1** | 100 Mbps | UTP 1쌍 (2선) | 차량 내부 배선 |
| **1000BASE-T1** | 1 Gbps | UTP 1쌍 (2선) | 고속 도메인 백본 |

**T1(1-pair) 규격의 특징**

- 단일 꼬임쌍(2선)으로 **전이중 통신** 수행
- 송신·수신 신호가 같은 선에 겹쳐 흐르며, 에코 캔슬러로 분리
- 배선 무게·부피 감소, 커넥터 크기 축소 → 차량 적용에 유리
- EMC 요구 조건이 엄격 (차량 환경의 노이즈 대응)

**외부 연결 시 문제와 해결**

- 일반 진단기·PC는 100BASE-TX(4선) 포트만 보유
- 차량 내부는 100BASE-T1(2선) 기반
- → **미디어 컨버터** 또는 **게이트웨이 내장 변환 회로**로 TX ↔ T1 변환 필요

```
  [PC / 진단기]        [변환]         [차량 내부]
   100BASE-TX  ──→  Media Converter  ──→  100BASE-T1
     RJ-45              (또는 GW 내장)        OBD-II
```

#### 4.2 OBD-II 커넥터 핀 할당

**ISO 13400-3 규정 핀 배치**

| 핀 | 신호 | 설명 |
| --- | --- | --- |
| **1** | **Activation Line** | DoIP 활성화 신호 |
| **3** | Ethernet RX+ | 수신 데이터 + |
| **8** | Ethernet TX+ | 송신 데이터 + |
| **11** | Ethernet RX− | 수신 데이터 − |
| **12** | Ethernet TX− | 송신 데이터 − |
| 4, 5 | Ground | 접지 |
| 16 | Battery + | 전원 |
| 6, 14 | CAN High / Low | 기존 CAN 진단 (병행 유지) |

**핵심 포인트**

- 기존 **CAN 진단 핀(6, 14)은 그대로 유지** → 하위 호환성 확보
- 이더넷은 기존 미사용 핀을 활용 → 커넥터 형상 변경 불필요
- 동일 커넥터로 CAN 진단과 DoIP 진단을 모두 수행 가능
- 진단기가 이더넷 링크를 확보하지 못하면 CAN으로 폴백하는 구성도 가능

#### 4.3 Activation Line

**Activation Line이란**

- OBD-II **1번 핀**에 인가하는 신호선
- 차량의 이더넷 진단 인터페이스를 **활성화하는 스위치 역할**
- 진단기가 이 핀에 전압을 인가하면, 차량이 DoIP 통신 준비 상태로 전환

**왜 필요한가**

| 이유 | 설명 |
| --- | --- |
| 소비 전력 절감 | 이더넷 PHY는 상시 동작 시 전력 소모가 큼 → 평소 비활성 유지 |
| 보안 | 물리적 접근 없이는 진단 인터페이스가 열리지 않음 |
| 오동작 방지 | 주행 중 불필요한 진단 포트 활성화 차단 |

**동작 순서**

```
  [1] 진단기 케이블 연결
  [2] Activation Line에 전압 인가 (핀 1)
  [3] 차량 측 이더넷 PHY 전원 인가 및 초기화
  [4] Ethernet Link Up (물리 링크 확립)
  [5] IP 주소 할당 절차 시작
  [6] DoIP 통신 가능 상태
```

- 케이블만 꽂고 Activation Line을 인가하지 않으면 **링크 자체가 올라오지 않음**
- 현장에서 "연결이 안 된다"고 할 때 가장 흔한 원인 중 하나

**전기적 특성**

- 차량 배터리 전압(약 12V) 수준의 신호 사용
- 차량 측은 이 신호를 감지하여 웨이크업 처리
- 세부 임계 전압·타이밍은 제조사 규격에 따름

#### 4.4 IP 주소 할당

**할당 방식 3가지**

| 방식 | 주소 범위 | 특징 |
| --- | --- | --- |
| **DHCP** | 서버 정책에 따름 | 표준 우선 방식, 서버 필요 |
| **AutoIP (Link-Local)** | IPv4: 169.254.x.x / IPv6: FE80:: | 서버 없이 자체 생성 |
| **고정 IP** | 사전 정의 | 개발·생산 환경에서 사용 |

**표준 권장 절차**

```
  [1] Link Up 후 DHCP DISCOVER 송신
  [2] 일정 시간 내 응답 수신 시 → 할당 주소 사용
  [3] 응답 없음 (타임아웃) → AutoIP로 폴백
  [4] AutoIP 주소 생성 후 ARP로 중복 확인
  [5] 중복 없으면 해당 주소 확정
```

- 진단기가 DHCP 서버 역할을 하는 구성이 일반적
- 차량이 클라이언트로 동작하여 주소를 할당받음
- DHCP 타임아웃 대기로 인해 **초기 연결에 수 초 지연**이 발생할 수 있음

**IPv6 사용**

- 차량 내부 네트워크는 IPv6 Link-Local 주소(FE80::) 사용 사례가 많음
- MAC 주소 기반으로 자동 생성되므로 별도 할당 절차 불필요
- 멀티캐스트 기반 탐색에 유리

#### 4.5 유선 vs 무선 연결 환경

**ISO 13400-3 : 유선 인터페이스**

- OBD-II 커넥터를 통한 직접 연결
- 대상 : A/S 정비소, 생산 라인, 개발 벤치
- 특징 : 물리적 접근 필요, 고속·안정적, Activation Line으로 제어

**무선(원격) 연결 환경**

```
  [진단 서버]
       │ 인터넷 / 이동통신망
       ▼
  [텔레매틱스 유닛 (TCU)]
       │ 차량 내부 이더넷
       ▼
  [중앙 게이트웨이]
       │
  [대상 ECU]
```

- TCU가 외부망과 차량 내부망을 연결하는 관문 역할
- Activation Line 없이 소프트웨어적으로 진단 세션 개시
- OTA 업데이트, 원격 고장 진단에 활용

**유선 / 무선 비교**

| 항목 | 유선 (OBD-II) | 무선 (원격) |
| --- | --- | --- |
| 활성화 방식 | Activation Line | 소프트웨어 인증 |
| 대역폭 | 100 Mbps ~ 1 Gbps | 이동통신망에 종속 |
| 지연 | 낮고 일정 | 변동 큼 |
| 보안 요구 | 물리 접근이 1차 방어 | **TLS·인증 필수** |
| 주 용도 | 정비, 생산, 개발 | OTA, 원격 진단 |

#### 4.6 연결 시 확인 사항

**단계별 점검 포인트**

| 단계 | 확인 항목 | 이상 시 증상 |
| --- | --- | --- |
| 물리 연결 | 케이블, 커넥터 접촉 | Link LED 미점등 |
| Activation Line | 핀 1 전압 인가 여부 | 링크 자체가 안 올라옴 |
| Link 확립 | 속도·듀플렉스 협상 | 통신 불안정, 패킷 손실 |
| IP 할당 | DHCP 응답 또는 AutoIP | ping 불가 |
| UDP 탐색 | 브로드캐스트 도달 여부 | 차량 응답 없음 |
| TCP 연결 | 포트 13400 개방 | 연결 거부 |

**흔한 문제 원인**

- Activation Line 미인가 → 가장 빈번한 원인
- 미디어 컨버터 미사용 또는 불량 (TX ↔ T1 변환 누락)
- 진단기 PC의 방화벽이 UDP 13400 브로드캐스트 차단
- 진단기와 차량이 서로 다른 서브넷에 위치
- 차량 슬립 모드 진입으로 이더넷 PHY 비활성
