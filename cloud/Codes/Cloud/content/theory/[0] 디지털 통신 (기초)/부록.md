## 6.1 16진수 대응표

### 기본 대응표 (0 ~ 15)

| 10진수 | 16진수 | 2진수 |
| --- | --- | --- |
| 0 | 0 | 0000 |
| 1 | 1 | 0001 |
| 2 | 2 | 0010 |
| 3 | 3 | 0011 |
| 4 | 4 | 0100 |
| 5 | 5 | 0101 |
| 6 | 6 | 0110 |
| 7 | 7 | 0111 |
| 8 | 8 | 1000 |
| 9 | 9 | 1001 |
| 10 | **A** | 1010 |
| 11 | **B** | 1011 |
| 12 | **C** | 1100 |
| 13 | **D** | 1101 |
| 14 | **E** | 1110 |
| 15 | **F** | 1111 |

> **이 표 하나면 충분합니다.** 나머지는 계산으로 해결됩니다.

---

### 자주 보는 값

| 16진수 | 10진수 | 비고 |
| --- | --- | --- |
| 0x00 | 0 | 최솟값 |
| 0x0A | 10 |  |
| 0x10 | 16 | 십이 아님 주의 |
| 0x20 | 32 |  |
| 0x32 | 50 |  |
| 0x40 | 64 |  |
| 0x50 | 80 |  |
| 0x64 | 100 |  |
| 0x80 | 128 | 절반 지점 |
| 0xC8 | 200 |  |
| 0xFF | **255** | 1바이트 최댓값 |

---

### 변환 방법 요약

**16진수 → 10진수 (두 자리)**

```
   앞자리 × 16 + 뒷자리

   예) 0xC8 = 12 × 16 + 8 = 200
```

**10진수 → 16진수**

```
   16으로 나눈 몫이 앞자리, 나머지가 뒷자리

   예) 200 ÷ 16 = 12 나머지 8  →  0xC8
```

**2진수 → 16진수**

```
   4자리씩 잘라서 위 표로 변환

   예) 1100 1000  →  C 8  →  0xC8
```

---

### 자릿수로 크기 판단하기

| 표기 자릿수 | 크기 | 표현 범위 |
| --- | --- | --- |
| 2자리 (0xFF) | 1바이트 | 0 ~ 255 |
| 4자리 (0xFFFF) | 2바이트 | 0 ~ 65,535 |
| 8자리 (0xFFFFFFFF) | 4바이트 | 0 ~ 약 42억 |

> **16진수 2자리 = 1바이트** 자릿수를 2로 나누면 바이트 수가 나옵니다.

## 6.2 단위 환산표

### 용량 단위

| 단위 | 크기 | 체감 기준 |
| --- | --- | --- |
| 1 바이트 (B) | 비트 8개 | 영어 글자 1개 |
| 1 KB | 약 1,000 B | A4 반 페이지 |
| 1 MB | 약 1,000 KB | 고화질 사진 1장 |
| 1 GB | 약 1,000 MB | 영화 1편 |
| 1 TB | 약 1,000 GB | 영화 1,000편 |

---

### 속도 단위

| 단위 | 초당 비트 | 초당 바이트 |
| --- | --- | --- |
| 1 Kbps | 1,000 | 125 B |
| 1 Mbps | 100만 | 125 KB |
| 100 Mbps | 1억 | **약 12.5 MB** |
| 1 Gbps | 10억 | 약 125 MB |

---

### b와 B 구분

| 표기 | 의미 | 쓰이는 곳 |
| --- | --- | --- |
| **b** (소문자) | bit, 비트 | 속도 |
| **B** (대문자) | Byte, 바이트 | 용량 |

```
   1 바이트 = 8 비트

   속도를 바이트로 바꾸려면 8로 나눕니다
```

> **기억할 기준** **8 Mbps = 1초에 1 MB**

---

### 통신 방식별 비교

| 방식 | 속도 | 한 덩어리 크기 |
| --- | --- | --- |
| CAN | 500 Kbps | 8 바이트 |
| CAN FD | 2 ~ 8 Mbps | 최대 64 바이트 |
| 이더넷 (100BASE) | 100 Mbps | 최대 약 1,500 바이트 |
| 이더넷 (1000BASE) | 1 Gbps | 최대 약 1,500 바이트 |

---

### 전송 시간 참고표 (10 MB 기준)

| 방식 | 이론상 | 실제 |
| --- | --- | --- |
| CAN | 약 3분 | 약 30분 |
| CAN FD | 약 20초 | 약 5분 |
| 이더넷 | 약 1초 | 약 30초 ~ 1분 |

> 실제 시간이 더 긴 이유 : 부가 정보, 대기 시간, 검증 절차

## 6.3 용어 정리

### 데이터 관련

| 용어 | 의미 |
| --- | --- |
| **비트 (bit)** | 0 또는 1 하나. 최소 단위 |
| **바이트 (Byte)** | 비트 8개 묶음. 256가지 표현 가능 |
| **2진수** | 0과 1만 쓰는 표기. 컴퓨터 내부 방식 |
| **10진수** | 0~9를 쓰는 표기. 사람의 일상 방식 |
| **16진수** | 0~9와 A~F를 쓰는 표기. 컴퓨터 값을 읽기 위한 방식 |
| **0x** | 16진수임을 나타내는 표시 |
| **아스키 (ASCII)** | 글자마다 번호를 붙여둔 국제 약속표 |

---

### 통신 관련

| 용어 | 의미 |
| --- | --- |
| **프로토콜** | 통신에 필요한 약속. 통신 규약 |
| **요청 / 응답** | 한쪽이 묻고 다른 쪽이 답하는 구조 |
| **긍정 응답** | 요청대로 처리했다는 답 |
| **부정 응답** | 처리할 수 없다는 답 (사유 포함) |
| **계층** | 내용과 전달 수단을 나눈 구조 |
| **캡슐화** | 전달에 필요한 정보를 겉에 덧붙이는 것 |
| **표준** | 제조사가 달라도 통하게 만든 공통 규격 |

---

### 신호 관련

| 용어 | 의미 |
| --- | --- |
| **노이즈** | 신호를 방해하는 원치 않는 전기적 간섭 |
| **꼬임쌍선** | 두 가닥을 꼬아 노이즈를 상쇄하는 배선 |
| **검사값** | 데이터가 손상되지 않았는지 확인하는 값 |
| **주소 / 식별자** | 여러 대 중 누구에게 보내는지 표시하는 꼬리표 |
| **덩어리 (프레임)** | 한 번에 전송하는 정보 묶음 |
| **bps** | bits per second. 초당 비트 수 |

---

### 자동차 관련

| 용어 | 의미 |
| --- | --- |
| **ECU** | 자동차 부품에 붙어 있는 소형 컴퓨터 |
| **CAN** | 자동차에서 널리 쓰이는 통신 방식 |
| **CAN FD** | CAN의 속도·용량 개선판 |
| **차량용 이더넷** | 자동차에 적용된 인터넷 연결 기술 |
| **UDS** | 진단 대화에 쓰는 표준 언어 |
| **DoIP** | 이더넷 기반 진단 통신 방식 |

---

### 표준 번호

| 번호 | 내용 |
| --- | --- |
| **ISO 14229** | 진단 대화 언어 (UDS) |
| **ISO 15765** | CAN 기반 진단 전송 |
| **ISO 13400** | 이더넷 기반 진단 전송 (DoIP) |
| **ISO 11898** | CAN 통신 규격 |

   0x가 붙으면 16진수

## 전체 자료 한 장 요약

```
   [1장] 컴퓨터는 0과 1만 쓴다
          8개를 묶어 1바이트, 256가지 표현
          글자도 번호로 바꿔 저장한다
                    ↓
   [2장] 0과 1은 너무 길어서 읽기 힘들다
          그래서 16진수를 쓴다
          1바이트 = 16진수 2자리
                    ↓
   [3장] 0과 1만 주고받아선 의미가 없다
          약속이 필요하다 = 프로토콜
          내용과 전달 수단은 나눠둔다 = 계층
                    ↓
   [4장] 전압 높낮이로 신호를 보낸다
          노이즈에 대응하려 두 가닥을 꼰다
          전선을 아끼려 여러 대가 공유한다
          그래서 주소가 필요하다
                    ↓
   [5장] 자동차 소프트웨어가 500배 커졌다
          기존 방식으론 30분, 이더넷은 1분
          이것이 기술 전환의 이유다
```
