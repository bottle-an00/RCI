# (4) 신호는 어떻게 오가는가

- **선수 학습** : 1~3장
- **이 장의 목표** : 통신 속도와 케이블 구조가 왜 그렇게 정해졌는지 이해하기

---

## 4.1 전선 위의 전압이 0과 1이 되는 원리

### 기본 아이디어

- 1장에서 컴퓨터가 0과 1만 쓴다고 했습니다
- 그 0과 1을 **전선으로 옮기는** 방법이 필요합니다

```
   전압이 높다  →  1
   전압이 낮다  →  0
```

### 시간에 따라 값을 바꿔가며 보냅니다

```
   전압
    ↑
 높 │  ┌──┐     ┌──┐  ┌──────┐
    │  │  │     │  │  │      │
 낮 │──┘  └─────┘  └──┘      └──→ 시간

        1  0  0  1  0  1  1  0
```

- 정해진 시간 간격마다 한 번씩 값을 읽습니다
- 그 간격이 짧을수록 **더 많은 정보를 보낼 수 있습니다**

### 여기서 속도의 개념이 나옵니다

| 1초에 보내는 신호 개수 | 표기 |
| --- | --- |
| 1,000개 | 1 Kbps |
| 500,000개 | 500 Kbps |
| 100,000,000개 | 100 Mbps |

- **bps** = bits per second, 초당 비트 수
- 자세한 내용은 5장에서 다룹니다

### 왜 무한정 빠르게 할 수 없는가

```
   신호를 너무 빨리 바꾸면?

   전압이 미처 다 오르기 전에 다음 신호가 오고,
   받는 쪽이 1인지 0인지 구분하지 못합니다
```

| 제약 요인 | 설명 |
| --- | --- |
| 전선의 길이 | 길수록 신호가 약해지고 늦게 도착 |
| 전선의 품질 | 재질과 굵기에 따라 한계가 다름 |
| 주변 환경 | 노이즈가 많으면 구분이 어려움 |

> **자동차와의 연결** 자동차 안은 엔진 진동, 온도 변화, 전자파가 심합니다. 그래서 사무실 네트워크만큼 쉽게 속도를 올릴 수 없습니다.

## 4.2 노이즈와 그 대응

### 노이즈란

- 원하지 않는 전기적 방해를 뜻합니다
- 신호에 섞여 들어가 값을 왜곡시킵니다

```
   [보낸 신호]        [노이즈]        [받은 신호]

    ┌──┐              ~~~~~           ┌~~┐
    │  │       +      ~~~~~     =     │  │~
   ─┘  └─             ~~~~~          ─┘  └~

                                    → 1인지 0인지 애매해짐
```

### 자동차 안의 노이즈 발생원

| 발생원 | 설명 |
| --- | --- |
| 엔진 점화 장치 | 강한 전기 스파크 |
| 각종 모터 | 창문, 와이퍼, 팬 |
| 발전기 | 전압 변동 |
| 외부 전파 | 방송, 통신 기지국 |

### 대응 1 — 전선 두 가닥을 꼬아서 쓴다

**꼬임쌍선(Twisted Pair)**

```
   두 가닥을 서로 꼬아 놓습니다

      ╱╲╱╲╱╲╱╲╱╲
      ╲╱╲╱╲╱╲╱╲╱
```

**원리**

```
   [1] 두 가닥에 서로 반대되는 신호를 보냅니다

       가닥 A :  ┌──┐
       가닥 B :  └──┘   (정반대)

   [2] 노이즈는 두 가닥에 똑같이 들어옵니다

       가닥 A :  ┌──┐ + 노이즈
       가닥 B :  └──┘ + 노이즈   (같은 노이즈)

   [3] 받는 쪽에서 두 값의 차이를 봅니다

       차이 = (A + 노이즈) − (B + 노이즈)
            = A − B          ← 노이즈가 상쇄됨
```

> **핵심** 노이즈를 **막는** 것이 아니라, 두 가닥에 똑같이 들어오게 해서 **빼버리는** 방식입니다.

- 꼬아 놓는 이유는 두 가닥이 **똑같은 환경**에 놓이게 하기 위해서입니다
- 나란히 두면 한쪽만 노이즈를 더 받을 수 있습니다

### 대응 2 — 오류를 검사한다

- 아무리 대비해도 오류는 발생합니다
- 그래서 데이터에 **검사용 값**을 함께 보냅니다

```
   보내는 쪽 : 데이터 + 검사값
   받는 쪽   : 데이터로 검사값을 다시 계산 → 비교

   일치      → 정상
   불일치    → 오류, 다시 보내달라고 요청
```

> **비유** 계좌이체를 할 때 예금주 이름을 확인하는 것과 비슷합니다. 계좌번호를 잘못 입력했는지 검증하는 장치입니다.

## 4.3 여러 대가 한 선을 나눠 쓰기

### 문제 상황

- 자동차 안에는 컴퓨터가 100개 이상 있습니다
- 모든 쌍을 각각 연결하면 전선이 감당할 수 없이 많아집니다

```
   [각각 연결하는 방식]        [하나의 선을 공유]

     ○───○───○                  ○   ○   ○
     │╲ ╱│╲ ╱│                  │   │   │
     │ ╳ │ ╳ │        vs      ──┴───┴───┴──
     │╱ ╲│╱ ╲│
     ○───○───○                  선 하나면 충분

   전선이 폭발적으로 증가
```

**전선이 늘어나면**

| 문제 | 영향 |
| --- | --- |
| 무게 증가 | 연비 악화 |
| 원가 증가 | 차량 가격 상승 |
| 공간 부족 | 배선 공간 확보 어려움 |
| 고장 위험 | 접점이 많을수록 불량 가능성 증가 |

### 해결 : 하나의 선을 함께 쓴다

- 여러 대가 **같은 전선에 연결**되어 있습니다
- 누군가 신호를 보내면 **모두가 듣습니다**

> **비유** 회의실에서 여러 사람이 대화하는 것과 같습니다. 한 사람이 말하면 방 안의 모두가 듣습니다.

### 그런데 문제가 생깁니다

```
   두 명이 동시에 말하면?

   → 소리가 겹쳐서 아무도 알아듣지 못합니다
```

**그래서 순서를 정하는 규칙이 필요합니다**

| 방법 | 설명 |
| --- | --- |
| 우선순위 | 급한 내용이 먼저 (브레이크 > 창문) |
| 대기 | 다른 사람이 말하는 중이면 기다림 |
| 재시도 | 충돌하면 잠시 후 다시 시도 |

> **자동차와의 연결** 자동차 통신에서는 **중요한 신호에 높은 우선순위**를 줍니다. 창문 조작 신호 때문에 브레이크 신호가 늦어지면 안 되기 때문입니다.

## 4.4 그래서 주소가 필요하다

### 모두가 듣는다면 어떻게 구분하는가

```
   전선 위로 신호가 흘러갑니다

   ──────────[신호]──────────
      │        │        │
     ECU A    ECU B    ECU C

   셋 다 이 신호를 받았습니다
   그런데 이건 누구에게 보낸 걸까요?
```

### 해결 : 신호에 꼬리표를 붙인다

```
   [받는 사람][내용]

   ECU B가 받으면 → "나한테 온 거네"  → 처리
   ECU A가 받으면 → "나한테 온 게 아니네" → 무시
   ECU C가 받으면 → "나한테 온 게 아니네" → 무시
```

- 이 꼬리표를 **주소** 또는 **식별자**라고 부릅니다
- 3장에서 본 택배 송장과 같은 역할입니다

### 주소는 미리 정해둡니다

| 방식 | 설명 |
| --- | --- |
| 고정 | 부품마다 번호를 미리 부여 |
| 할당 | 연결될 때 번호를 받음 |

> 자동차 부품은 대부분 **고정 방식**입니다. 설계 단계에서 어느 부품이 몇 번인지 정해집니다.

### 주소는 두 가지 방식으로 쓰입니다

**1대1 — 특정 대상에게만**

```
   "3번 부품, 상태 알려줘"
   → 3번만 대답
```

**1대다 — 여러 대에게 한꺼번에**

```
   "모두, 지금 상태 알려줘"
   → 해당하는 모두가 각자 대답
```

| 방식 | 언제 쓰는가 |
| --- | --- |
| 1대1 | 특정 부품을 자세히 진단할 때 |
| 1대다 | 전체 상태를 한 번에 확인할 때 |

> **자동차와의 연결** 정비소에서 "전체 고장 코드 조회"를 누르면 1대다 방식이 쓰입니다. 특정 부품을 수리할 때는 1대1 방식을 씁니다.

## 4.5 한 번에 얼마나 보낼 수 있는가

### 신호는 덩어리로 보냅니다

- 0과 1을 하나씩 계속 흘려보내지 않습니다
- **정해진 크기의 덩어리**로 묶어서 보냅니다

```
   [꼬리표][내용][검사값]
   └────── 한 덩어리 ──────┘
```

**왜 덩어리로 보내는가**

| 이유 | 설명 |
| --- | --- |
| 구분 | 어디서 시작해 어디서 끝나는지 알 수 있음 |
| 순서 양보 | 한 덩어리 끝나면 다른 부품이 말할 기회 |
| 오류 관리 | 덩어리 단위로 검사하고 재전송 |

### 덩어리 크기가 통신 방식마다 다릅니다

| 통신 방식 | 한 덩어리에 담기는 내용 |
| --- | --- |
| CAN | **8바이트** |
| CAN FD | 최대 64바이트 |
| 이더넷 | 최대 약 1,500바이트 |

### 8바이트가 얼마나 작은가

```
   8바이트 = 영어 글자 8개

   "HELLO123"  ← 딱 이만큼
```

**차대번호를 보내려면**

```
   차대번호 = 17바이트

   CAN(8바이트)로는 한 번에 못 보냄
   → 여러 덩어리로 나눠서 보내야 함
```

### 나눠 보내면 손해가 생깁니다

```
   [한 덩어리 구조]

   ┌────────┬──────────────┬────────┐
   │ 꼬리표  │   실제 내용   │ 검사값 │
   └────────┴──────────────┴────────┘
     └─── 부가 정보 ───┘

   덩어리를 나눌수록 부가 정보가 반복해서 붙습니다
```

**비유**

> 책 한 권을 엽서로 나눠 보낸다고 생각해봅시다. 엽서마다 주소를 다시 써야 하고, 순서 번호도 붙여야 합니다. 엽서가 많아질수록 **주소 쓰는 시간**이 전체 시간의 상당 부분을 차지합니다.

### 그래서 덩어리 크기가 중요합니다

| 덩어리 크기 | 큰 데이터 전송 시 |
| --- | --- |
| 작음 (8바이트) | 나누는 횟수 많음 → 부가 정보 부담 큼 |
| 큼 (1,500바이트) | 나누는 횟수 적음 → 효율적 |

> **자동차와의 연결** 자동차 소프트웨어는 수십 MB입니다. 8바이트씩 나눠 보내면 **수백만 번**을 나눠야 합니다. 이것이 새로운 통신 방식이 필요해진 핵심 이유입니다. 구체적인 계산은 5장에서 해봅니다.

## 4장 정리

| 개념 | 핵심 |
| --- | --- |
| 신호 전달 | 전압의 높낮이로 0과 1을 표현 |
| 노이즈 | 두 가닥을 꼬아서 상쇄 + 검사값으로 오류 검출 |
| 선 공유 | 전선을 줄이기 위해 여러 대가 하나의 선을 함께 사용 |
| 주소 | 모두가 듣기 때문에 대상을 지정하는 꼬리표가 필요 |
| 덩어리 | 정해진 크기로 묶어서 전송, 크기가 효율을 좌우 |

**한 장 요약**

```
   전압의 높낮이로 0과 1을 보낸다
                ↓
   자동차 안은 노이즈가 심하다
                ↓
   두 가닥을 꼬고, 검사값을 붙여 대응한다
                ↓
   전선을 줄이려고 여러 대가 하나의 선을 공유한다
                ↓
   모두가 듣게 되므로 주소가 필요하다
                ↓
   신호는 정해진 크기의 덩어리로 보낸다
                ↓
   덩어리가 작으면 큰 데이터를 보낼 때 손해가 크다
```

> 5장에서는 지금까지의 내용을 **숫자로 계산**해봅니다. "8바이트씩 보내면 실제로 얼마나 걸리는가"를 직접 구해보면, 회사가 왜 새로운 통신 방식으로 옮겨가는지 명확해집니다.
