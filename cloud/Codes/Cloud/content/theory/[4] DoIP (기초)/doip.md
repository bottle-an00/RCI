# [4] DoIP (기초)

- **대상** : 전사 임직원 (구매/재경/인사/법무 등 비전공 직군)
- **목표** : 왜 자동차 진단이 인터넷 기술로 옮겨가고 있는지 이해하기
- **선수 지식** : [기초] UDS 진단 통신 이해하기

---

## 들어가기 전에

**이 문서를 읽고 나면 알 수 있는 것**

- DoIP가 무엇이고, 기존 방식과 무엇이 다른지
- 왜 업계 전체가 이 방식으로 옮겨가고 있는지
- 원격 진단·무선 업데이트가 어떻게 가능해지는지

**앞 문서와의 관계**

> UDS 기초편에서 **"자동차와 대화하는 언어"** 를 배웠다면, 이번에는 **"그 대화를 어떤 통로로 주고받을 것인가"** 를 다룹니다.

---

## 1. DoIP 개요 — 좁은 길에서 넓은 길로

**1.1 한 문장 정의**

> **DoIP는 자동차 진단 대화를 인터넷 기술 위에서 주고받는 방식입니다.**

- **Do**gnostics **o**ver **I**nternet **P**rotocol의 줄임말
- 우리말로는 **인터넷 프로토콜 기반 진단 통신**
- 국제 표준 **ISO 13400**으로 규격화

---

## 1.2 언어는 그대로, 통로만 바뀐다

**가장 중요한 개념**

| 구분 | 담당 | 바뀌는가 |
| --- | --- | --- |
| **대화 내용** (무엇을 물어볼 것인가) | UDS | **바뀌지 않음** |
| **전달 통로** (어떻게 전달할 것인가) | DoIP | **바뀜** |

**비유**

```
   같은 편지를 보내는 두 가지 방법

   [기존]  우편으로 발송   →  느리지만 확실함
   [DoIP]  이메일로 발송   →  훨씬 빠름

   편지에 쓰인 언어와 내용은 완전히 동일합니다
```

- "고장 코드 알려줘"라는 요청 자체는 두 방식에서 똑같습니다
- 그것을 전달하는 수단만 달라집니다

> **실무적 의미** 기존에 쌓아온 UDS 지식과 진단 시나리오가 그대로 유효합니다. 새 기술이 기존 자산을 버리게 만들지 않는다는 점이 이 설계의 핵심입니다.

---

## 1.3 왜 바꿔야 했는가

**문제의 시작 : 소프트웨어가 너무 커졌다**

| 시기 | 자동차 컴퓨터 1대의 프로그램 용량 |
| --- | --- |
| 2000년대 초 | 수십~수백 KB |
| 현재 | 수십 MB 이상 (자율주행 관련은 더 큼) |

- 용량이 **수천 배** 늘었습니다
- 그런데 그것을 전달하는 통로의 속도는 거의 그대로였습니다

**현실에서 벌어진 일**

| 현장 | 문제 |
| --- | --- |
| 생산 공장 | 차 1대 소프트웨어 설치에 라인이 감당 못 할 시간 소요 |
| 정비소 | 컴퓨터 1개 업데이트에 수십 분~수 시간, 고객 대기 |
| 리콜 | 수만 대 대상 작업 시 총 비용이 감당 불가 수준 |

**비유로 이해하기**

> 예전에는 A4 몇 장을 보내면 됐는데, 이제는 책 한 권을 보내야 합니다. 그런데 여전히 우편으로 한 장씩 보내고 있었던 셈입니다.

---

## 1.4 얼마나 빨라지는가

**속도 비교**

| 방식 | 통신 속도 | 비유 |
| --- | --- | --- |
| CAN (기존) | 500 Kbps | 좁은 골목길 |
| CAN FD | 2~8 Mbps | 2차선 도로 |
| **이더넷 (DoIP)** | **100 Mbps ~ 1 Gbps** | **고속도로** |

**실제 작업 시간**

| 방식 | 소프트웨어 1개 교체 |
| --- | --- |
| CAN | 약 30분 ~ 1시간 |
| CAN FD | 약 5 ~ 10분 |
| **DoIP** | **약 30초 ~ 수 분** |

> **주의할 점** 통로가 빨라지면 이제 **자동차 컴퓨터 자체의 처리 속도**가 새로운 한계가 됩니다. 고속도로를 뚫었더니 이번엔 목적지 주차장이 좁은 상황과 비슷합니다.

---

## 2. DoIP 프로토콜 스택 — 무엇을 빌려 쓰는가

**2.1 검증된 기술을 그대로 가져왔다**

**DoIP가 사용하는 것**

- 우리가 매일 쓰는 **인터넷 기술 그대로**입니다
- IP 주소, 이더넷 케이블, TCP 같은 기술을 자동차에 적용

**이것이 왜 유리한가**

| 항목 | 효과 |
| --- | --- |
| 이미 검증됨 | 수십 년간 전 세계가 사용한 안정적 기술 |
| 인력 확보 용이 | 네트워크 엔지니어를 활용 가능 |
| 도구가 이미 존재 | 범용 네트워크 분석 도구 사용 가능 |
| 개발 부담 감소 | 데이터 분할·재전송을 직접 만들 필요 없음 |

---

## 2.2 인터넷 기술이 대신 해주는 일

**기존 CAN 방식에서 직접 해야 했던 것**

```
   큰 데이터를 보내야 할 때

   [CAN]   데이터를 7바이트씩 잘게 쪼개서
           하나씩 순서 맞춰 보내고
           중간에 빠진 게 없는지 직접 확인해야 함

   [DoIP]  그냥 통째로 보내면
           인터넷 기술이 알아서 쪼개고,
           순서 맞추고, 빠진 건 다시 보내줌
```

**비유**

> 이사할 때 직접 짐을 나르는 것과 이사 업체를 부르는 것의 차이입니다. 업체가 포장·운반·순서 정리를 알아서 해줍니다.

---

## 2.3 두 가지 통신 수단을 나눠 쓴다

| 상황 | 쓰는 방법 | 비유 |
| --- | --- | --- |
| **상대를 찾을 때** | 전체에게 외치기 | "여기 차량 계신가요?" 하고 부르기 |
| **대화할 때** | 1:1 연결 | 상대를 찾은 뒤 마주 앉아 대화 |

- 처음에는 상대의 주소를 모르므로 **전체에게 방송**합니다
- 응답이 오면 그때부터 **1:1로 확실하게** 주고받습니다

---

## 3. DoIP 네트워크 구성 — 누가 누구와 이야기하는가

**3.1 등장인물**

| 주체 | 역할 | 비유 |
| --- | --- | --- |
| **진단기** | 질문하는 쪽 (우리 제품) | 방문객 |
| **게이트웨이** | 차량의 대표 창구 | 건물 안내데스크 |
| **각 컴퓨터(ECU)** | 실제 진단 대상 | 각 층의 사무실 |

---

## 3.2 게이트웨이가 모든 것을 중계한다

```
        [진단기]
            │
            ▼
    ┌───────────────┐
    │  게이트웨이    │   ← 차량의 대표 창구
    └───┬───────┬───┘
        │       │
    빠른 길   느린 길
        │       │
    [최신 부품] [기존 부품]
    (이더넷)   (기존 CAN)
```

**핵심 포인트**

- 진단기는 **게이트웨이 한 곳에만 연결**합니다
- "3층 사무실 연결해주세요"라고 하면 안내데스크가 연결해 줍니다
- 대상이 최신 부품인지 기존 부품인지 **진단기는 신경 쓸 필요 없습니다**

> **비용 관점에서 중요한 점** 이 구조 덕분에 **기존 부품을 전부 교체하지 않아도** DoIP를 도입할 수 있습니다. 자동차 제조사 입장에서 전환 비용을 크게 낮춰주는 설계입니다.

---

## 3.3 다만, 느린 구간은 여전히 느리다

| 대상 | 속도 |
| --- | --- |
| 이더넷에 직접 연결된 부품 | 빠름 (DoIP 효과 온전히 발휘) |
| 게이트웨이 뒤편의 기존 부품 | 여전히 느림 |

- 고속도로를 타고 왔어도, 마지막 골목길은 여전히 좁습니다
- 그래서 자동차 제조사는 **자주 업데이트하는 부품부터** 이더넷으로 옮기고 있습니다

---

## 3.4 차량을 어떻게 구별하는가

**공장에서는 여러 대가 동시에 연결되어 있습니다**

- 그래서 자동차는 자신을 소개할 때 **차대번호(VIN)** 를 함께 알려줍니다
- 진단기는 이를 보고 "내가 작업할 차가 맞는지" 확인합니다

> 아직 차대번호가 부여되지 않은 신차는 부품 고유번호로 구별합니다.

---

## 4. 연결 절차와 보안 — 아무나 못 들어온다

**4.1 기존 방식보다 절차가 복잡해졌다**

**비교**

```
   [기존 CAN]
    케이블 연결  →  바로 대화 시작

   [DoIP]
    케이블 연결  →  차량 찾기  →  연결하기
                 →  허가받기  →  대화 시작
```

**왜 복잡해졌는가**

| 이유 | 설명 |
| --- | --- |
| 여러 대가 공존 | 네트워크에 누가 있는지 먼저 찾아야 함 |
| 원격 접근 가능 | 물리적으로 멀리서도 접속 가능 → 신원 확인 필수 |
| 자원 관리 | 동시에 몇 대까지 연결할지 제한 필요 |

> **제품 관점에서의 의미** 절차가 늘어난 만큼 **연결 단계에서 발생하는 문제도 늘어납니다.** 진단기가 얼마나 안정적으로 연결하고, 실패했을 때 원인을 얼마나 친절히 알려주느냐가 제품 품질을 좌우합니다.

---

## 4.2 진단 포트를 켜는 스위치

**Activation Line**

- 자동차의 이더넷 진단 기능은 **평소 꺼져 있습니다**
- 진단기를 꽂고 **특정 신호를 보내야 켜집니다**

**왜 꺼두는가**

| 이유 | 설명 |
| --- | --- |
| 전력 절약 | 상시 켜두면 배터리 소모 |
| 보안 | 물리적으로 접근하지 않으면 열리지 않음 |
| 안전 | 주행 중 불필요한 활성화 방지 |

> **현장 참고** "진단기를 꽂았는데 아무 반응이 없다"는 문의의 상당수가 이 신호 관련 문제입니다. 고객 지원 담당자가 알아두면 좋은 항목입니다.

---

## 4.3 커넥터는 그대로다

- 자동차의 진단 커넥터(운전석 아래) **모양은 바뀌지 않았습니다**
- 기존에 비어 있던 자리에 이더넷 신호를 배정했습니다
- 기존 CAN 진단용 자리도 **그대로 유지**됩니다

**의미**

| 관점 | 효과 |
| --- | --- |
| 자동차 | 커넥터 설계 변경 불필요 |
| 정비소 | 기존 차량과 신차를 같은 자리에 연결 |
| 진단기 | 두 방식을 모두 지원하는 제품 설계가 가능 |

---

## 4.4 보안이 훨씬 중요해졌다

**위험이 커진 이유**

| 기존 CAN | DoIP |
| --- | --- |
| 차 옆에 직접 가야만 접근 가능 | 통신망을 통해 원격 접근 가능 |
| 전용 장비와 지식 필요 | 널리 알려진 인터넷 기술 |

> 물리적 접근이라는 **가장 강력한 1차 방어선이 사라진** 셈입니다.

**그래서 여러 겹의 잠금 장치를 둡니다**

| 단계 | 방어 수단 |
| --- | --- |
| 1단계 | 진단 포트 자체를 평소 꺼둠 |
| 2단계 | 통신 내용 암호화 |
| 3단계 | 연결 시 신원 확인 및 허가 |
| 4단계 | 각 부품별 권한 확인 (UDS 보안 인증) |

**법규 사항**

| 규제 | 내용 |
| --- | --- |
| **UN R155** | 차량 사이버보안 관리체계 요구 |
| **UN R156** | 소프트웨어 업데이트 관리체계 요구 |

> **법무·인증 담당자 참고** 두 규제는 권고가 아니라 **형식승인의 필수 요건**입니다. 미충족 시 해당 시장에서 차량 판매 자체가 불가하므로, 고객사가 협력사에게도 관련 요구사항을 전달하는 경우가 있습니다.

---

## 5. 실제 활용 — 무엇이 가능해지는가

**5.1 정비소 : 대기 시간 단축**

**기존**

> "소프트웨어 업데이트가 필요합니다. 한 시간 정도 걸립니다."

**DoIP 적용 후**

> "소프트웨어 업데이트가 필요합니다. 몇 분이면 됩니다."

| 효과 | 설명 |
| --- | --- |
| 고객 만족도 | 대기 시간 감소 |
| 정비소 수익성 | 같은 시간에 더 많은 차량 처리 |
| 인건비 | 작업자 1인당 처리량 증가 |

---

## 5.2 생산 공장 : 라인 속도 확보

- 공장은 차량이 **정해진 시간 안에** 각 공정을 통과해야 합니다
- 소프트웨어 설치 시간이 이 시간을 넘기면 라인 전체가 멈춥니다
- DoIP는 이 병목을 해소합니다

> 하루 수백~수천 대를 생산하는 공장에서, 차 1대당 몇 분은 곧 생산량 차이로 직결됩니다.

---

## 5.3 원격 진단 : 가지 않고 진단하기

```
   [고객 차량]  ─── 통신망 ───  [제조사 진단 센터]

   차량이 도로 위에 있어도
   센터에서 상태를 확인할 수 있습니다
```

**가능해지는 일**

| 사례 | 내용 |
| --- | --- |
| 사전 안내 | 입고 전에 원인을 파악해 부품을 미리 준비 |
| 고장 예측 | 이상 징후를 조기에 감지 |
| 데이터 축적 | 실제 주행 데이터를 개발에 반영 |

---

## 5.4 무선 업데이트(OTA) : 정비소에 가지 않기

**개념**

> 스마트폰이 밤사이 알아서 업데이트되듯, 자동차도 그렇게 하는 것

**절차 (개념)**

```
   [1] 제조사가 업데이트 배포
   [2] 차량이 통신망으로 내려받음
   [3] 내용이 위조되지 않았는지 검증
   [4] 안전한 상태인지 확인 (주차 중, 배터리 충분)
   [5] 소유자 동의 확인
   [6] 차량 내부에서 설치
   [7] 검증 후 적용 (실패 시 원래대로 복구)
```

**사업적 의미**

| 관점 | 영향 |
| --- | --- |
| 제조사 | 리콜 비용 대폭 절감 |
| 소비자 | 정비소 방문 불필요 |
| 진단기 업계 | **정비소 방문형 작업 일부가 줄어들 수 있음** |

> **주목할 점** OTA 확산은 진단기 업계에 위협이자 기회입니다. 단순 업데이트 작업은 줄어들지만, 차량 데이터 분석과 원격 진단 도구 수요는 늘어납니다. 회사의 제품 방향과 직결되는 변화입니다.

---

## 5.5 전환은 한 번에 일어나지 않는다

**현실**

| 구분 | 상황 |
| --- | --- |
| 신차 | DoIP 지원 확대 중 |
| 기존 차량 | 여전히 CAN 방식 |
| 과도기 차량 | 두 방식 혼재 |

**진단기에 요구되는 것**

- **두 방식을 모두 지원**해야 합니다
- 연결된 차량이 어느 방식인지 자동으로 판별해야 합니다
- 이 대응 능력이 제품 경쟁력의 핵심입니다

> 도로 위 차량 대부분이 DoIP로 교체되기까지는 **10년 이상**이 걸립니다. 그동안 두 방식을 모두 다뤄야 합니다.

## 6. [부록] 용어 정리 및 업무 연결

**6.1 자주 들리는 용어**

| 용어 | 의미 |
| --- | --- |
| **DoIP** | 인터넷 기술 기반 자동차 진단 통신 방식 |
| **CAN** | 기존에 널리 쓰이는 차량 통신 방식 |
| **차량용 이더넷** | 자동차에 적용된 인터넷 연결 기술 |
| **게이트웨이** | 차량의 대표 통신 창구 역할을 하는 부품 |
| **Activation Line** | 이더넷 진단 기능을 켜는 신호선 |
| **Routing Activation** | 연결 후 진단 권한을 허가받는 절차 |
| **논리 주소** | 차량 안에서 각 부품을 구별하는 번호 |
| **플래싱** | 자동차 소프트웨어를 교체하는 작업 |
| **OTA** | 무선 소프트웨어 업데이트 |
| **TLS** | 통신 내용을 암호화하는 기술 |

## 6.3 한 장 요약

```
  자동차 소프트웨어가 수천 배 커졌다
                    ↓
  기존 통신 방식으로는 전달에 너무 오래 걸린다
                    ↓
  이미 검증된 인터넷 기술을 가져다 쓰기로 했다
                    ↓
  그것이 DoIP  (대화 언어인 UDS는 그대로)
                    ↓
  속도가 수백 배 빨라졌다  (수십 분 → 수 분)
                    ↓
  대신 연결 절차가 복잡해지고 보안이 중요해졌다
                    ↓
  원격 진단과 무선 업데이트가 가능해졌다
                    ↓
  전환에는 10년 이상 걸리므로
  당분간 두 방식을 모두 지원해야 한다
```
