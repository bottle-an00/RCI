# (3) 컴퓨터 네트워크 개요

## **3. 컴퓨터 네트워크 개요**

## **3.1 네트워크란?**

- **네트워크: 통신 기술을 이용하여 구축하는 연결망을 지칭하는 용어**
  - **노드(Node): 서버, 라우터, 스위치 등 네트워크 장치**
  - **링크(Link): 유선 또는 무선**
  - **LAN: 좁은 공간의 근거리 통신망 (유선 LAN → Ethernet, 무선 LAN → Wi-Fi)**

---

## **3.2 OSI 7 Layers**

- **ISO에서 개발한 컴퓨터 네트워크 프로토콜 디자인으로, 통신을 계층으로 나누어 설명하는 모델**
- **배경: 1980년대 초반 같은 제조사의 통신 장비만 연결 가능했던 호환성 문제를 해결하기 위해 개발**
- **OSI 7계층은 네트워크의 이론적 기술을 위한 모델이고, TCP/IP 4계층은 구현에 중점을 둔 모델**

| **Layer** | **이름** | **역할** |
| --- | --- | --- |
| **7** | **Application** | **사용자와 가장 가까운 프로그램** |
| **6** | **Presentation** | **데이터 형식 변환 및 압축/암호화** |
| **5** | **Session** | **통신 연결 유지 및 설정** |
| **4** | **Transport** | **신뢰할 수 있는 데이터 전송** |
| **3** | **Network** | **주소를 지정하고 최적의 경로 설정** |
| **2** | **Data Link** | **기기 간 물리적 전달 및 오류 제어** |
| **1** | **Physical** | **전기적 신호를 주고받는 HW 단계** |

### **3.2.1 OSI 7계층 vs TCP/IP 4계층**

**실무에서 실제로 구현·사용하는 것은 TCP/IP 모델이며, OSI는 개념 설명과 문제 진단(트러블슈팅) 시의 공용 언어로 주로 활용된다.**

| **OSI 7계층** | **TCP/IP 4계층** | **차량 네트워크 대응 요소** |
| --- | --- | --- |
| **Application, Presentation, Session** | **Application** | **SOME/IP, DoIP, HTTP(OTA 서버 통신 등)** |
| **Transport** | **Transport** | **TCP, UDP** |
| **Network** | **Internet** | **IP(IPv4/IPv6)** |
| **Data Link, Physical** | **Network Access(Link)** | **이더넷 MAC/PHY, CAN Controller/Transceiver** |

```

```

> **OSI가 7단계로 세분화한 것을 TCP/IP는 4단계로 통합한 이유는, 실제 통신 구현에서 Presentation/Session의 역할이 Application 계층 안에서 함께 처리되는 경우가 많기 때문이다. 이후 다룰 SOME/IP, DoIP는 모두 "TCP/IP 4계층" 관점에서 Application 계층의 프로토콜로 이해하면 된다.**

## **3.3 물리 계층 (1계층)**

- **데이터 통신을 위한 물리적 신호 및 배선의 종류, 커넥터 등을 담당**
- **0, 1을 어떻게 물리적으로 표현할지 정의함**
  - **광통신: 빛의 세기로 0, 1을 표현**
  - **CAN 통신: CAN\_H, CAN\_L의 전압차로 0, 1을 표현**
- **0, 1 표현 방법에 따른 전송 매체**
  - **광통신: 광섬유 케이블**
  - **CAN 통신: 2가닥 꼬임 구리선**
  - **유선 LAN 케이블: 트위스트 페어 케이블 (구리선)**

**(그림: 트위스트 페어 케이블 사진, LAN 케이블 커넥터 사진)**

## **3.4 데이터 링크 계층 (2계층)**

- **물리적 연결을 이용하여 네트워크 내 주변 장치 간의 신뢰성 있는 정보 전송을 담당함**
- **두 장치 간의 정보 전달을 위해 주소가 할당됨**

  - **이더넷의 경우 MAC 주소가 할당되며, 장치마다 생성될 때 고유 주소가 할당됨**
- **NIC(Network Interface Card): 이더넷 I/O 모듈**

  - **네트워크를 통한 데이터 전송 및 수신 역할을 담당**

### **3.4.1 MAC 주소**

- **NIC에는 고유의 식별 코드가 들어있고, 이를 MAC 주소로 불림 (6 Byte)**
- **MAC 주소 덕분에 네트워크를 통해 데이터가 출발지에서 목적지까지 정확하게 도착 가능**
- **구조: `OUI(3 Byte, 제조사 식별) + NIC 고유번호(3 Byte)` — 예: `AC:DE:48:12:34:56`**
  - **앞 3바이트(OUI, Organizationally Unique Identifier)는 IEEE가 제조사에 할당**
  - **뒤 3바이트는 제조사가 자체적으로 부여하는 일련번호**

> **차량 적용 시 참고: 차량 내 이더넷 ECU에도 각각 고유 MAC 주소가 부여되지만, 완성차 업체에 따라서는 진단/관리 편의를 위해 MAC 주소와 별개로 논리적인 로컬 IP 주소 체계를 고정 할당(Static IP)하여 운영하는 경우가 많다 (3.9절 참고).**

---

## **3.5 네트워크 계층 (3계층)**

- **여러 개의 네트워크를 거쳐 목적지까지 도달할 수 있도록 노드를 거칠 때마다 경로를 찾아주는 역할을 하는 계층**
- **라우팅, 흐름제어, 세그멘테이션, 오류제어, 인터네트워킹 등을 수행**
- **인터넷 프로토콜(IP)가 네트워크 계층에 해당함**
  - **목적지 주소까지 전달될 수 있도록 중간지마다 MAC 주소를 변경하면서 전달됨**

### **3.5.1 IP 주소**

- **네트워크 계층에서 수신지와 목적지 컴퓨터의 주소를 지정하기 위해 사용하는 주소**
- **인터넷에서 유일한 값이어야 함**
  - **IPv4: 111.11.150.1 (4Byte)**
  - **IPv6: 1050:0000:0000:0000:0005:0600:300c:326b (16Byte)**

### **3.5.2 서브넷(Subnet)과 서브넷 마스크**

- **IP 주소를 네트워크 영역(Network ID)과 호스트 영역(Host ID)으로 나누어, 같은 네트워크에 속하는 장치인지 판별하는 데 사용**
- **서브넷 마스크 예: `255.255.255.0` → 앞 3바이트는 네트워크 영역, 마지막 1바이트만 호스트 구분에 사용 (호스트 254개까지 수용 가능)**

> **차량 적용 예: Zonal Architecture에서는 존(Zone)별로 서브넷을 나누어 관리하는 경우가 많다. 예를 들어 전방 Zone은 `192.168.1.0/24`, 후방 Zone은 `192.168.2.0/24`처럼 구획하면, 각 존 내부 트래픽이 다른 존으로 불필요하게 전달되지 않아 네트워크 부하와 보안 측면에서 유리하다.**

### **3.5.3 DNS (Domain Name Server)**

- **"google.com"과 같이 문자열로 된 도메인 주소를 IP 주소로 변경해주는 서버**
- **도메인 주소 및 IP 주소 어느 것을 사용해서 실제 통신에는 IP 주소가 사용됨**

> **차량 적용 참고: 일반 인터넷처럼 사람이 읽는 도메인명을 쓰는 대신, 차량 내부망은 대부분 고정 IP 또는 SOME/IP SD(Service Discovery, 8장 참고)와 유사한 서비스 탐색 방식을 사용한다. 다만 OTA 업데이트, 클라우드 연동 등 외부 인터넷과 통신할 때는 일반적인 DNS 체계를 그대로 활용한다.**

### **3.5.4 라우터와 라우팅**

- **라우터: 목적지가 정해지면 해당 목적지로 가는 경로를 알려주는 장비**
- **라우팅: IP 주소로 목적지를 지정하고 난 후에는, 해당 목적지까지 어떤 경로로 데이터를 보낼지 결정하는 행위**

> **차량 적용 참고: 차량 내부에서는 일반적으로 "라우터"라는 별도 장비 대신, 존 게이트웨이(Zone Gateway) 또는 중앙 HPC가 라우팅 기능을 함께 수행한다. 존 간 트래픽을 어디로 보낼지 결정하는 라우팅 테이블은 차량 설계 시점에 대부분 고정(Static Routing)되어 있어, 일반 인터넷망처럼 동적으로 경로가 바뀌는 경우는 드물다.**

## **3.6 전송 계층 (4계층) - TCP와 UDP**

**원문 자료에는 명시적으로 다루지 않지만, 이후 등장하는 DoIP(TCP 기반)와 SOME/IP(주로 UDP 기반)를 이해하려면 전송 계층의 두 프로토콜 차이를 먼저 알아야 한다.**

| **구분** | **TCP** | **UDP** |
| --- | --- | --- |
| **연결 방식** | **연결 지향(Connection-oriented) - 3-way handshake로 연결 수립 후 통신** | **비연결(Connectionless) - 연결 수립 절차 없이 즉시 전송** |
| **신뢰성** | **순서 보장, 재전송을 통한 손실 복구** | **순서·재전송 보장 없음(전송 후 확인하지 않음)** |
| **속도/오버헤드** | **상대적으로 느림(핸드셰이크, 재전송 등 오버헤드)** | **상대적으로 빠름(오버헤드 최소)** |
| **차량 내 활용 예** | **DoIP(진단), 대용량 파일 전송(OTA 패키지)** | **SOME/IP(대부분의 서비스 통신), 실시간 센서 스트리밍** |

> **선택 기준: 데이터가 하나라도 누락되면 안 되는 경우(진단 명령, 소프트웨어 파일)는 TCP를, 신선도(latency)가 중요하고 일부 패킷 손실을 허용할 수 있는 경우(센서 값 스트리밍처럼 다음 주기 데이터가 곧 다시 오는 경우)는 UDP를 선택하는 것이 일반적이다.**

## **3.7 Encapsulation / Decapsulation**

- **계층을 내려갈 때마다 헤더가 하나씩 씌워지는 것을 캡슐화(Encapsulation), 계층을 올라갈 때 헤더를 하나씩 제거하는 것을 \*\*역캡슐화(Decapsulation)\*\*라 한다.**
- **구조: `[MAC[IP[TCP/UDP[ Data ]]]]`**
- **송신 측은 Application → Physical 방향으로 캡슐화, 수신 측은 Physical → Application 방향으로 역캡슐화한다.**

### **3.7.1 계층별 헤더 오버헤드 예시**

**실제로 애플리케이션 데이터 1000 Byte를 보낸다고 가정했을 때, 각 계층을 지나며 추가되는 헤더 크기의 대략적인 예:**

| **계층** | **추가되는 헤더** | **대략적 크기** |
| --- | --- | --- |
| **Application (SOME/IP 등)** | **서비스 ID, 메서드 ID 등** | **약 16 Byte** |
| **Transport (UDP)** | **출발지/목적지 포트 등** | **8 Byte** |
| **Network (IP)** | **출발지/목적지 IP 등** | **20 Byte(IPv4 기준)** |
| **Data Link (Ethernet)** | **MAC 주소, 타입 등** | **18 Byte(FCS 포함)** |

**→ 결과적으로 1000 Byte의 실제 데이터를 보내기 위해 최종적으로는 약 1062 Byte가 전선 위로 전송된다.**

> **이 오버헤드 개념은 실무에서 대역폭 산정(Bandwidth Budget) 시 중요하게 고려된다. 특히 짧은 주기로 작은 데이터를 자주 보내는 경우, 헤더 오버헤드 비율이 데이터 자체보다 커질 수 있어 통신 설계 시 유의해야 한다.**

---

## **3.8 IP 주소, MAC 주소 비교**

| **구분** | **MAC 주소** | **IP 주소** |
| --- | --- | --- |
| **계층** | **2계층 Data Link** | **3계층 Network** |
| **역할** | **같은 LAN 안에서 장치 식별** | **네트워크 간 목적지 식별** |
| **범위** | **로컬 네트워크 내부** | **다른 네트워크까지 확장** |
| **변경 가능 여부** | **원칙적으로 고정(하드웨어에 내장)** | **네트워크 구성에 따라 변경 가능** |
| **차량 적용 시 관리 주체** | **부품 제조 시점에 고유 할당** | **시스템 설계 시점에 고정 할당(Static)하는 경우가 많음** |

- **MAC 주소: NIC마다 부여되는 6바이트 고유 식별 코드. 네트워크를 통해 데이터가 출발지에서 목적지까지 정확하게 도착하도록 함**
- **IP 주소: 여러 네트워크 중 목적지까지 갈 수 있도록 논리 주소를 부여하고 경로를 결정. 차량의 경우 OTA, V2X, 원격진단 등 외부 네트워크 통신을 위해 필수**

### **3.8.1 ARP (Address Resolution Protocol)**

- **IP 주소를 통해 MAC 주소를 알아내는 프로토콜**
- **같은 네트워크 안의 장치와 통신하려면, IP 주소만으로는 실제 이더넷 프레임을 보낼 수 없고 상대방의 MAC 주소가 반드시 필요하기 때문에 이 변환 과정이 필요함**

## **3.9 차량 내 IP 주소 체계 설계 예시 (참고)**

**실제로 차량 이더넷 네트워크를 설계할 때 자주 쓰이는 방식을 단순화한 예시:**

| **존(Zone) / 도메인** | **서브넷 예시** | **비고** |
| --- | --- | --- |
| **전방 Zone ECU** | **192.168.10.0/24** | **카메라, 레이더 등** |
| **후방 Zone ECU** | **192.168.20.0/24** | **후방 카메라, 주차 센서 등** |
| **인포테인먼트 도메인** | **192.168.30.0/24** | **IVI, 내비게이션** |
| **진단 포트(OBD/DoIP)** | **192.168.100.0/24 (고정, 예시)** | **정비소 진단기 연결 시 사용되는 대역** |
| **중앙 HPC / 게이트웨이** | **192.168.1.1 등 각 서브넷의 대표 IP** | **존 간 라우팅 담당** |

> **위 수치는 이해를 돕기 위한 단순화된 예시이며, 실제 서브넷 설계는 완성차 업체별 내부 표준(예: 특정 대역 예약, VLAN ID와의 매핑 규칙 등)에 따라 달라진다. 다만 "왜 차량 내부에도 IP 주소 체계 설계가 필요한가"를 이해하는 데는 이 정도 그림으로 충분하다.**

## **3.10 정리 - 이 장에서 다음 장으로 이어지는 흐름**

- **(3)장에서 다룬 OSI/TCP-IP 계층 구조, MAC/IP 주소, TCP/UDP 개념은 이후 (4) Data Link Layer(이더넷 프레임 구조)와 (8) SOME/IP(서비스 지향 통신)를 이해하기 위한 기반 지식이다.**
- **특히 "MAC 주소는 로컬에서, IP 주소는 네트워크 간 목적지를 찾는다"는 구분과 "TCP는 신뢰성, UDP는 속도"라는 트레이드오프는 뒤에 나올 DoIP·SOME/IP 설계 근거를 이해하는 데 반복적으로 쓰인다.**
