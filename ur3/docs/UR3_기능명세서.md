# miniGIT UR3(로봇) 기능명세서

*Functional Specification — UR3 Robot Arm*

- 문서번호: MINIGIT-FUNC-UR3-001
- 버전: 0.1 (초안)
- 작성일: 2026-07-29
- 분류: 학습용 (내부)
- 상위 문서: UR3 진단 통신 사양서 (작성 예정)

> 본 문서는 UR3 로봇팔의 하드웨어 구성과, 각 진단 서비스(0x22/0x2E/0x2F/0x31)가 호출되었을 때 로봇 측에서 실제로 어떤 동작이 일어나는지를 정의한다.
> 프로토콜(SID/DID/RID/DTC/NRC 값)은 UR3 진단 통신 사양서에서 확정된 것을 따른다.
> 세션/보안/제어권 상태 관리와 MQTT 프레임 처리는 RCI가 수행하며, 이는 본 문서 범위 밖이다(UR3 RCI 기능명세서 참조).

---

## 1. 범위 (Scope)

UR3는 UDS 유사 진단 프로토콜을 직접 이해하지 못하는 순수 구동 대상이다. RCI가 UDS 서버(진단 에이전트) 역할을 겸하며, RTDE(텔레메트리 읽기 겸 모션 제어)와 Dashboard(텍스트 명령) 인터페이스, 그리고 그리퍼/카메라 등 부속 장치와의 자체 연결을 통해 UR3를 조회/구동한다.

책임:
- RTDE/Dashboard로 조회 가능한 로봇 상태값과, 그리퍼/카메라 등 부속 장치의 자체 연결 상태를 조합하여 진단 DID로 노출
- Dashboard 명령 / RTDEControlInterface 모션 호출로 로봇을 구동
- 로봇 측 물리적 조건(안전 모드, 온도, 전압 등)을 DTC 발생 조건으로 정의

범위 밖:
- MQTT 진단 요청 해석, 세션/보안/제어권 상태 관리, DTC 저장/소거 로직 (RCI 담당 — UR3 RCI 기능명세서 참조)
- PC 웹 진단 앱 UI
- RC카 진단 대상 (별개 세트, 본 프로젝트 범위 외)

## 2. 하드웨어 구성 (Hardware)

### 2.1 로봇 및 통신 인터페이스

| 구성 | 부품/방식 | 인터페이스 | 비고 |
|---|---|---|---|
| 로봇 본체 | UR3 (CB-Series, PolyScope 3.x) | — | — |
| 컨트롤 박스 | UR CB3 컨트롤박스 | Ethernet | RTDE/Dashboard 서버 구동 |
| 텔레메트리 읽기 | RTDEReceiveInterface | TCP 30004 | ur_rtde 라이브러리, CB-Series 최대 125Hz, 최신값 캐시 |
| 모션 제어 | RTDEControlInterface (moveJ/moveL/stopJ/stopL) | TCP 30004 | ur_rtde 라이브러리, 연결 유지 중 로봇에 제어 스크립트 상주 |
| 프로그램/전원/안전 제어 | Dashboard Server | TCP 29999 | 텍스트 명령 |
| 그리퍼 | 비례 제어 그리퍼 (0~100% 위치) | UR 컨트롤박스 디지털/아날로그 I/O | 위치 감지 센서 없음(확정). 정확한 신호 방식(아날로그 또는 디지털) 가안, 실제 배선 확인 필요 |
| 카메라 | 로봇 장착 카메라 | (연결 상태만 진단 대상) | 영상 스트리밍은 범위 밖, 이미지 캡처는 §3.4.2 참조 |
| RCI ↔ 컨트롤박스 연결 | Ethernet(TCP/IP) | — | 공식 인터페이스 문서 기준으로는 CAN이 확인되지 않아 미사용 |

### 2.2 센서/상태 항목 (0x22 읽기 대상, DID 0x01xx)

| DID | 항목 | 취득 소스 | 응답 길이/타입 | 인코딩 |
|---|---|---|---|---|
| 0x0101 | 조인트 각도(6축) | `actual_q` | 12B, 6×int16 | 0.1도 단위 |
| 0x0102 | 조인트 속도(6축) | `actual_qd` | 12B, 6×int16 | 0.1도/초 단위 |
| 0x0103 | 조인트 온도(6축) | `joint_temperatures` | 12B, 6×int16 | 0.1도(섭씨) 단위 |
| 0x0104 | 조인트 전류(6축) | `actual_current` | 12B, 6×int16 | mA 단위 |
| 0x0105 | TCP 위치(x,y,z) | `actual_TCP_pose[0..2]` | 6B, 3×int16 | 0.1mm 단위 |
| 0x0106 | TCP 자세(rx,ry,rz) | `actual_TCP_pose[3..5]` | 6B, 3×int16 | 0.001rad 단위 |
| 0x0107 | 로봇 모드 | `robot_mode` | 1B, int8 | 값 자체가 의미 (2.2.1) |
| 0x0108 | 안전 모드 | `safety_mode` | 1B, uint8 | 값 자체가 의미 (2.2.2) |
| 0x0109 | 프로그램 실행 상태 | `runtime_state` | 1B, uint8 | 값 자체가 의미 (2.2.3) |
| 0x010A | 로봇 전압 | `actual_robot_voltage` | 2B, uint16 | mV 단위 |
| 0x010B | 로봇 전류 | `actual_robot_current` | 2B, uint16 | mA 단위 |
| 0x010C | 속도 스케일링 | `speed_scaling` | 2B, uint16 | 0.1% 단위 |
| 0x010D | 안전 상태 비트 | `safety_status_bits` | 2B, uint16 bitfield | 2.2.4 참조. 가안, 실기 확인 필요(§7 A3) |
| 0x010E | 로드된 프로그램명 | Dashboard `get loaded program` | 가변, ASCII | 문자열 그대로 |
| 0x010F | 그리퍼 상태 | RCI가 보관한 마지막 명령값 echo (위치 감지 센서 없음, 확정) | 1B, uint8 | 0~100(%) |
| 0x0110 | 카메라 상태 | RCI의 카메라 장치 연결 확인 (RTDE/Dashboard 무관) | 1B, uint8 | 0=연결안됨, 1=연결됨 |

모든 다바이트 값은 빅엔디안, int16 음수는 2의 보수.

#### 2.2.1 로봇 모드 값 (0x0107)

| 값 | 의미 | 값 | 의미 |
|---|---|---|---|
| -1 | NO_CONTROLLER | 4 | POWER_ON |
| 0 | DISCONNECTED | 5 | IDLE |
| 1 | CONFIRM_SAFETY | 6 | BACKDRIVE |
| 2 | BOOTING | 7 | RUNNING |
| 3 | POWER_OFF | 8 | UPDATING_FIRMWARE |

#### 2.2.2 안전 모드 값 (0x0108)

| 값 | 의미 | 값 | 의미 |
|---|---|---|---|
| 1 | NORMAL | 6 | SYSTEM_EMERGENCY_STOP |
| 2 | REDUCED | 7 | ROBOT_EMERGENCY_STOP |
| 3 | PROTECTIVE_STOP | 8 | VIOLATION |
| 4 | RECOVERY | 9 | FAULT |
| 5 | SAFEGUARD_STOP | | |

#### 2.2.3 프로그램 실행 상태 값 (0x0109)

| 값 | 의미 | 값 | 의미 |
|---|---|---|---|
| 0 | STOPPING | 3 | PAUSING |
| 1 | STOPPED | 4 | PAUSED |
| 2 | PLAYING | 5 | RESUMING |

PAUSED(일시정지)는 현재 실행 위치와 자세를 유지한 채 실행만 멈춘 상태로 RESUMING을 거쳐 이어서 실행할 수 있다. STOPPED(정지)는 실행을 완전히 종료한 상태로, 다시 실행하려면 PLAYING으로 처음부터 시작해야 한다.

#### 2.2.4 안전 상태 비트 (0x010D, 가안)

b0=normal, b1=reduced, b2=protective stopped, b3=recovery, b4=safeguard stopped, b5=system e-stop, b6=robot e-stop, b7=emergency stopped, b8=violation, b9=fault, b10=stopped due to safety

### 2.3 액추에이터/제어 항목 (0x2F 강제 구동 대상, DID 0x02xx)

| DID | 항목 | 제어 데이터 | 제어 소스 | 전제조건 |
|---|---|---|---|---|
| 0x0201 | 프로그램 실행 제어 | 1B: 0=정지/1=재생/2=일시정지 | Dashboard `stop`/`play`/`pause` | 확장 세션 |
| 0x0202 | 속도 슬라이더 | 1B: 0~100(%) | RTDE IO `speed_slider_fraction` | 확장 세션 |
| 0x0203 | 전원/브레이크 | 1B: 0=전원끄기/1=전원켜기/2=브레이크해제 | Dashboard `power off`/`power on`/`brake release` | 보안 접근 완료 |
| 0x0204 | 안전 복구 | 1B: 1=보호정지해제/2=팝업닫기/3=안전재시작 | Dashboard `unlock protective stop`/`close safety popup`/`restart safety` | 보안 접근 완료 |
| 0x0206 | 그리퍼 제어 | 1B: 0~100(%), 0=완전열림/100=완전닫힘 | 그리퍼 I/O (신호 방식 가안, 실제 배선 확인 필요) | 확장 세션 |

세부 동작 설명(왜 특정 항목만 보안 접근이 필요한지, returnControlToECU 동작 등)은 §3(서비스별 기능 명세)에서 다룬다.

### 2.4 모션 제어 대상 (0x31 RoutineControl, RID 0x03xx)

| RID | 이름 | 파라미터 | 필요 권한 |
|---|---|---|---|
| 0x0301 | MoveJoint | 6축 목표각(12B, 0.1도) + 속도(1B,%) + 가속도(1B,%) | 확장 세션 + 보안 접근 완료 |
| 0x0302 | MoveLinear | TCP 위치(6B, 0.1mm) + TCP 자세(6B, 0.001rad) + 속도(1B,%) + 가속도(1B,%) | 확장 세션 + 보안 접근 완료 |
| 0x0303 | MoveToWaypoint | 웨이포인트 인덱스(1B) | 확장 세션 |
| 0x0304 | 이미지 캡처 | — | 가안, 추후 논의 |
| 0x0305 | Wave (인사 동작 시연) | 속도(1B,%) + 가속도(1B,%) + 반복횟수(1B,1~10) | 확장 세션 + 보안 접근 완료 |

모션 제어는 RTDEControlInterface(moveJ/moveL)로 수행되며, 1차 안전장치는 로봇 자체 세이프티 존(PolyScope Installation 설정)이다. 실행/중단/결과 조회 흐름은 §3에서 다룬다.

## 3. 진단 서비스별 기능 명세 (Service Specifications)

각 서비스는 **입력(요청) → 처리(전제조건·동작) → 출력(응답/NRC)** 형식으로 기술한다.

### 3.1 ReadDataByIdentifier (0x22)

- **입력**: `22 [DID_H] [DID_L]`
- **처리**: DID → 취득 소스 매핑(§2.2 상태 대역 / 아래 사양 대역). 세션 무관 읽기 허용.
  - 로봇 통신 두절(RTDE 수신 두절 또는 Dashboard TCP 재접속 실패) 상태에서는 `7F 22 22`(conditionsNotCorrect) 반환
  - 미정의 DID → `7F 22 31`(requestOutOfRange)
- **출력(긍정)**: `62 [DID_H] [DID_L] [데이터...]`
- **대상 DID**: §2.2(0x01xx 상태), 아래 사양 대역(0xF1xx)

**사양/식별 정보 (0xF1xx)**

| DID | 항목 | 타입 | 디코딩 |
|---|---|---|---|
| 0xF199 | SW 업데이트 날짜 | 3B BCD | YYMMDD |
| 0xF195 | SW 버전(PolyScope) | 가변 ASCII | 문자열 그대로 (예 "3.15.8") |
| 0xF18C | 시리얼 번호 | 가변 ASCII | 문자열 그대로. 가안, 실기에서 `get serial number` 지원 여부 확인 필요(현재는 RCI 설정 파일 수기값 반환) |
| 0xF1A0 | 로봇 IP 주소 | 4B uint8×4 | IPv4 옥텟 그대로 |

```
요청: 22 01 07     응답: 62 01 07 07              # 로봇 모드 RUNNING
요청: 22 F1 99     응답: 62 F1 99 26 07 27         # 2026-07-27
요청: 22 01 55     응답: 7F 22 31                  # 미정의 DID
요청: 22 01 01     응답: 7F 22 22                  # 로봇 통신 두절
```

### 3.2 WriteDataByIdentifier (0x2E)

- **입력**: `2E [DID_H] [DID_L] [데이터...]`
- **전제조건**: 확장 세션 + 보안 접근 완료(미충족 시 `7F 2E 33` / `7F 2E 22`)
- **처리**: 대상은 사양 대역(0xF1xx) 중 쓰기 가능 항목(0xF199, 0xF18C, 0xF1A0). 0xF195는 쓰기 불가(`7F 2E 31`)
  - **0xF1A0 설명**: 이 값을 쓰면 실제 UR3 컨트롤박스의 네트워크 설정이 바뀌는 것이 아니라, RCI가 접속을 시도할 대상 IP가 RCI 설정 파일에 저장된다. RCI는 기존 연결을 끊고 새 IP로 재접속을 시도하며, 값이 실제 로봇 IP와 다르면 RCI가 접속에 실패한다. 실제 로봇의 IP 변경은 PolyScope 화면에서 직접 해야 하며 이 프로토콜로는 불가능하다.
- **출력(긍정)**: `6E [DID_H] [DID_L]`

```
요청: 2E F1 A0 C0 A8 01 66     응답: 6E F1 A0            # 확장세션+보안완료 후 IP 변경
요청: 2E F1 A0 C0 A8 01 66     응답: 7F 2E 33            # 보안 미완료 상태에서 쓰기
요청: 2E F1 95 33 2E 31 35     응답: 7F 2E 31            # 쓰기 불가 항목
```

### 3.3 InputOutputControlByIdentifier (0x2F) — 강제 구동

포맷: `2F [DID_H] [DID_L] [IOControlParameter] [제어데이터...]`
IOControlParameter: `0x03`=강제 조정(shortTermAdjustment), `0x00`=제어권 반환(returnControlToECU)

#### 3.3.1 프로그램 실행 제어 (0x0201)

| 항목 | 내용 |
|---|---|
| 제어 데이터 | 1B: 0=정지, 1=재생, 2=일시정지 |
| 처리 | Dashboard `stop` / `play` / `pause` 호출 |
| 전제조건 | 확장 세션(보안 접근 불필요 — 이미 로드된 프로그램의 재생/정지/일시정지는 일상적 조작이고 안전 설정은 그대로 유지되기 때문) |
| returnControlToECU(0x00) | 정지 상태로 복귀 |

```
요청: 2F 02 01 03 01     응답: 6F 02 01 03 01        # 재생
요청: 2F 02 01 00        응답: 6F 02 01 00            # 정지(제어권 반환)
```

#### 3.3.2 속도 슬라이더 (0x0202)

실행 속도를 0~100%로 조절하는 안전장치 배율. 프로그램 재생이든 모션 명령(0x31)이든 관계없이 로봇의 실제 이동 속도에 곱해진다.

| 항목 | 내용 |
|---|---|
| 제어 데이터 | 1B: 0~100(%) |
| 처리 | RTDE IO `speed_slider_fraction` 설정 |
| 전제조건 | 확장 세션(보안 접근 불필요) |
| returnControlToECU(0x00) | 100%로 복귀 |

```
요청: 2F 02 02 03 32     응답: 6F 02 02 03 32         # 속도 슬라이더 50%
```

#### 3.3.3 전원/브레이크 (0x0203)

UR 로봇은 전원이 꺼지면 각 관절에 물리적 브레이크가 걸려 팔이 중력으로 떨어지지 않는다. 전원을 켠 뒤에도 브레이크는 자동으로 풀리지 않고 별도 해제 명령이 필요하다.

| 항목 | 내용 |
|---|---|
| 제어 데이터 | 1B: 0=전원 끄기, 1=전원 켜기, 2=브레이크 해제 |
| 처리 | Dashboard `power off` / `power on` / `brake release` 호출 |
| 전제조건 | 보안 접근 완료 필요(미충족 시 `7F 2F 33`) — 로봇을 실제로 움직일 수 있는 상태로 만드는 조작이라 아무나 실행하면 위험하기 때문 |
| 소요 시간 | 브레이크 해제는 수 초 소요 → 진행중 통지(`7F 2F 78`) 후 최종 응답 |
| returnControlToECU(0x00) | 개념 없음, `7F 2F 31` |

```
요청: 2F 02 03 03 02     중간: 7F 2F 78     최종: 6F 02 03 03 02   # 브레이크 해제
요청: 2F 02 03 03 01     응답: 7F 2F 33                             # 보안 미완료
```

#### 3.3.4 안전 복구 (0x0204)

| 값 | 동작 | 설명 |
|---|---|---|
| 1 | 보호정지 해제 | 충돌 등으로 감지되는 보호정지를 풀어 재동작 가능하게 함. 정지 발생 후 최소 5초 경과해야 해제 허용 |
| 2 | 안전 팝업 닫기 | 안전 이벤트 발생 시 뜨는 확인 팝업을 원격으로 닫음 |
| 3 | 안전 재시작 | 더 심각한 안전 결함 발생 시 안전 서브시스템 자체를 재시작 |

| 항목 | 내용 |
|---|---|
| 제어 데이터 | 1B: 1/2/3 (위 표) |
| 처리 | Dashboard `unlock protective stop` / `close safety popup` / `restart safety` 호출 |
| 전제조건 | 보안 접근 완료 필요(미충족 시 `7F 2F 33`) — 안전 정지 상태를 해제하는 것은 멈춘 이유를 무시하고 다시 움직이게 하는 조작이기 때문 |
| returnControlToECU(0x00) | 개념 없음, `7F 2F 31` |

```
요청: 2F 02 04 03 01     응답: 7F 2F 37               # 보호정지 후 5초 미경과
```

#### 3.3.5 그리퍼 제어 (0x0206)

| 항목 | 내용 |
|---|---|
| 제어 데이터 | 1B: 0~100(%). 0=완전 열림, 100=완전 닫힘 |
| 처리 | 그리퍼 I/O(§2.1, 가안)로 위치 명령 전송. 위치 감지 센서 없음(확정)이므로 성공 시 해당 값을 "마지막 명령값"으로 갱신(0x22 0x010F 읽기에 반영) |
| 전제조건 | 확장 세션(보안 접근 불필요, 0x0201/0x0202와 동일 수준) |
| NRC | 0x31(101 이상 범위 밖), 0x13(길이) |
| returnControlToECU(0x00) | 개념 없음, `7F 2F 31` |

```
요청: 2F 02 06 03 32     응답: 6F 02 06 03 32         # 50%만 닫기
요청: 2F 02 06 03 65     응답: 7F 2F 31               # 101은 범위 밖
```

**0x0201과 모션 명령(0x31)의 관계**: UR 컨트롤러는 새 동작(모션 명령이든 프로그램 재생이든)을 지시하는 순간 진행 중이던 다른 동작을 중단시킨다. 모션 명령 실행 중 0x0201로 재생을 시도하면 `7F 2F 22`, 반대로 재생 중 모션 명령을 시도하면 `7F 31 22`가 반환된다(§3.4 참조).

### 3.4 RoutineControl (0x31)

#### 3.4.1 모션 실행 (RID 0x03xx)

서브펑션: 0x01 startRoutine / 0x02 stopRoutine / 0x03 requestRoutineResults

| RID | 이름 | 파라미터 | 필요 권한 |
|---|---|---|---|
| 0x0301 | MoveJoint | 6축 목표각(12B, 0.1도) + 속도(1B,%) + 가속도(1B,%) | 확장 세션 + 보안 접근 완료 |
| 0x0302 | MoveLinear | TCP 위치(6B, 0.1mm) + TCP 자세(6B, 0.001rad) + 속도(1B,%) + 가속도(1B,%) | 확장 세션 + 보안 접근 완료 |
| 0x0303 | MoveToWaypoint | 웨이포인트 인덱스(1B) | 확장 세션 |
| 0x0305 | Wave (인사 동작 시연) | 속도(1B,%) + 가속도(1B,%) + 반복횟수(1B,1~10) | 확장 세션 + 보안 접근 완료 |

자유 관절/TCP 이동(0x0301/0x0302)은 사전정의 웨이포인트 이동(0x0303)보다 위험도가 높아 보안 접근을 추가로 요구한다(0x0203/0x0204와 동일 수준). Wave(0x0305)도 손목을 크게 왕복시키는 자유 동작이라 같은 수준의 권한을 요구한다.

**요청 흐름**

```
1. 시작:      31 01 [RID] [파라미터...]  ->  71 01 [RID] 00        # 즉시 접수
2. 진행 확인: 31 03 [RID]                 ->  7F 31 78              # 진행중
3. 완료 확인: 31 03 [RID]                 ->  71 03 [RID] 01 [결과][실행시간]   # 성공
                                          또는 71 03 [RID] 02 [중단시점][사유코드]  # 실패
4. 중단(언제든): 31 02 [RID]              ->  71 02 [RID] 00
```

**stopRoutine은 RID와 무관하게 실제 실행 중인 모션을 멈춘다**(동시에 하나만 실행 가능하므로 구분 불필요). 실행 중인 모션이 없어도 로봇 통신이 살아있으면 항상 `71 02 [RID] 00`을 반환한다. 단, 로봇 통신이 두절된 상태에서는 다른 서비스와 동일하게 `7F 31 22`를 반환한다 — 정지 명령이 실제로 로봇에 전달됐는지 확인할 수 없는 상태에서 소프트웨어가 성공을 자처하면, 운영자가 실제로는 멈추지 않은 로봇을 멈췄다고 오인할 위험이 있기 때문이다. 1차 안전장치는 로봇 자체 세이프티 존(§7 참조)이며, 통신 두절 시의 최종 정지는 이 물리적 안전장치와 비상정지 버튼에 의존한다.

```
요청: 31 01 03 01 00 00 FC 7C 00 00 FC 7C 00 00 00 00 1E 1E
      (관절 목표각 [0.0,-90.0,0.0,-90.0,0.0,0.0]도, 속도 30%, 가속도 30%)
응답: 71 01 03 01 00
요청: 31 03 03 01     응답: 71 03 03 01 01 00 00 FC 7C 00 00 FC 7C 00 00 00 00 00 64
                                                          # 성공, 실행시간 10.0초
요청: 31 02 03 01     응답: 71 02 03 01 00               # 언제든 중단
```

**NRC 매핑**

| 상황 | 응답 |
|---|---|
| default 세션에서 시도 | `7F 31 7F` |
| 자유 모션에서 보안 미완료 | `7F 31 33` |
| 목표값/미정의 RID 범위 밖 | `7F 31 31` |
| 이미 실행 중인 모션에 새로 시작 시도 | `7F 31 21` |
| 시작한 적 없는 RID에 결과 조회 | `7F 31 24` |
| 로봇 통신 두절 중 시도 | `7F 31 22` |
| 프로그램 재생(0x0201) 중 모션 시도 | `7F 31 22` |

#### 3.4.2 이미지 캡처 (RID 0x0304)

가안, 추후 논의. 현재 방향은 startRoutine으로 촬영을 트리거하고, requestRoutineResults 응답에는 이미지 데이터 자체가 아니라 촬영 완료 여부와 참조값만 담는 것이다. 실제 이미지 파일 전달 방식(URL, 별도 토픽 등)은 미확정.

## 4. 드라이버 계층 상세 (Driver Layer)

### 4.1 상태 드라이버 (0x01xx)

| DID | 원시 취득 | 인코딩 변환 | 오류 시 |
|---|---|---|---|
| 0x0101 조인트 각도 | `actual_q` (rad, 6축) | rad→deg×10 (int16) | 통신 두절 시 DTC 0x900002 |
| 0x0102 조인트 속도 | `actual_qd` (rad/s) | rad/s→deg/s×10 | 〃 |
| 0x0103 조인트 온도 | `joint_temperatures` (℃) | ℃×10 | 1축 이상 50.0℃ 초과 시 DTC 0xC20101 |
| 0x0104 조인트 전류 | `actual_current` (A) | A×1000=mA | 통신 두절 시 DTC 0x900002 |
| 0x0105 TCP 위치 | `actual_TCP_pose[0..2]` (m) | m→0.1mm | 〃 |
| 0x0106 TCP 자세 | `actual_TCP_pose[3..5]` (rad) | rad×1000 | 〃 |
| 0x0107 로봇 모드 | `robot_mode` | 그대로(1B) | 〃 |
| 0x0108 안전 모드 | `safety_mode` | 그대로(1B) | 값에 따라 DTC 0xB10001~0xB10004 |
| 0x0109 실행 상태 | `runtime_state` | 그대로(1B) | — |
| 0x010A 로봇 전압 | `actual_robot_voltage` (V) | V×1000=mV | 44.0V 미만 시 DTC 0xC20201 |
| 0x010B 로봇 전류 | `actual_robot_current` (A) | A×1000=mA | — |
| 0x010C 속도 스케일링 | `speed_scaling` (0~1) | ×1000 (0.1% 단위) | — |
| 0x010D 안전 상태 비트 | `safety_status_bits` | 비트필드 그대로 | 가안(§7 A3) |
| 0x010E 로드된 프로그램명 | Dashboard `get loaded program` | ASCII 그대로 | — |
| 0x010F 그리퍼 상태 | RCI가 보관한 마지막 명령값 | 그대로(1B) | — |
| 0x0110 카메라 상태 | RCI의 카메라 연결 확인 | 0/1(1B) | 연결 끊김 시 DTC 0xC20301 |

> 모든 다바이트 값은 빅엔디안. int16 음수는 2의 보수.

### 4.2 제어 드라이버 (0x02xx)

| DID | 제어 방식 |
|---|---|
| 0x0201 | Dashboard `stop` / `play` / `pause` 텍스트 명령 |
| 0x0202 | RTDE IO `speed_slider_fraction` 설정 |
| 0x0203 | Dashboard `power off` / `power on` / `brake release` |
| 0x0204 | Dashboard `unlock protective stop` / `close safety popup` / `restart safety` |
| 0x0206 | 그리퍼 I/O 출력(신호 방식 가안, 실제 배선 확인 필요) |

### 4.3 모션 드라이버 (RTDEControlInterface, RID 0x03xx)

| RID | 호출 | 완료 확인 |
|---|---|---|
| 0x0301 MoveJoint | `moveJ(q, speed, accel, async=True)` | `getAsyncOperationProgress()` 폴링 |
| 0x0302 MoveLinear | `moveL(pose, speed, accel, async=True)` | 〃 |
| 0x0303 MoveToWaypoint | 사전정의 웨이포인트 좌표 조회 후 `moveJ`/`moveL` 호출 | 〃 |
| stopRoutine(모든 RID 공통) | `stopJ()` / `stopL()` | 즉시 |

**안전장치**: 1차 방어선은 로봇 자체 세이프티 존(PolyScope Installation의 Joint Limits/Plane 제한, UDS로 원격 변경 불가). 소프트웨어 사전 검증으로 목표값 범위 확인(범위 밖 `7F 31 31`), 속도/가속도 서버측 상한 clamp, 동시 1개 모션만 허용(`7F 31 21`), 런어웨이 방지 타임아웃(§7 A6)을 적용한다.

## 5. DTC 관리 (Fault Handling)

### 5.1 DTC 정의

| DTC | 항목 | 발생 조건 |
|---|---|---|
| 0x900002 | 로봇 통신 두절 | RTDE 수신 두절 또는 Dashboard TCP 재접속 실패 |
| 0xB10001 | 비상정지(E-Stop) | 안전 모드 = 6 또는 7 |
| 0xB10002 | 보호정지 | 안전 모드 = 3 |
| 0xB10003 | 세이프가드 정지 | 안전 모드 = 5 |
| 0xB10004 | 안전 위반/폴트 | 안전 모드 = 8 또는 9 |
| 0xC20101 | 조인트 과온 | 조인트 온도 1축 이상 50.0℃ 초과. UR 안전 프로세서가 이 온도부터 경고를 로그에 남기는 시점에 맞춰, 실제 로봇이 스스로 안전정지를 거는 약 85℃보다 미리 경보하기 위함(§7 A2) |
| 0xC20201 | 로봇 저전압 | 로봇 전압 44.0V 미만. 48V 공급 규격(허용오차 ±1%, 정상 범위 약 47.5~48.5V) 대비 약 8% 여유를 두어, 정상적인 공급 전압 변동에는 반응하지 않으면서 실제 이상 저하만 감지하기 위함(§7 A2) |
| 0xC20301 | 카메라 연결 끊김 | 카메라 상태(0x0110) 확인 실패 |

### 5.2 감지/복귀 정책

감지 시 상태 0x08(confirmedDTC) 설정. 정상 복귀해도 상태는 유지되며, 소거는 0x14로만 가능(RC카 세트와 동일 정책). 감시 주체는 RCI `dtc_monitor`(권장 500ms 주기)이며, 저장소/조회/소거 로직 자체는 RCI가 수행한다(UR3 RCI 기능명세서 참조). 본 절은 발생 조건만 정의한다.

## 7. 가정 및 확정 필요 항목 (Assumptions & TBD)

| # | 항목 | 상태 |
|---|---|---|
| A1 | 인코딩 스케일 | 가정: 각도 0.1°, 온도 0.1℃, 전압 mV, 전류 mA, TCP 0.1mm/0.001rad |
| A2 | DTC 임계값 | 가정: 과온 50.0℃ — UR 안전 프로세서의 경고 로그 시점과 맞춰 실제 안전정지(약 85℃)보다 앞서 조기 경보하려는 목적. 저전압 44.0V — 48V±1% 공급 규격(정상 범위 약 47.5~48.5V) 대비 약 8% 여유를 두어 정상 변동과 실제 이상을 구분하려는 목적. 감시 주기 500ms. 모두 정확한 공식 임계값 문서가 없어 잠정치이며 실측 후 확정 필요 |
| A3 | safety_status_bits(0x010D) | 가안 — 이 값은 로봇의 여러 안전 상태(정상/감속/보호정지/비상정지 등)를 하나의 숫자 안에 비트별로 나눠 담은 것이다(예: 3번째 비트가 1이면 보호정지 상태). 이 필드가 비교적 최근 소프트웨어에 추가된 것으로 보여, 우리가 쓰는 CB3(PolyScope 3.x)에서 정상적으로 지원되는지 불확실하다. RTDE는 지원하지 않는 필드를 요청 목록에 넣으면 연결 자체를 거부할 수 있어, 실기에서 직접 테스트하기 전까지 가안으로 둔다. 미지원으로 확인되면 안전 모드(0x0108) 값만으로 필요한 구분(정상/보호정지/비상정지 등)을 대체한다 |
| A4 | 시리얼 번호(0xF18C) 취득 | 가안 — `get serial number` 실기 지원 확인 필요. 미확정 시 RCI 설정 파일 수기값 폴백 |
| A5 | 이미지 캡처 전달 방식 | 가안 — 추후 논의(§3.4.2) |
| A6 | 모션 런어웨이 방지 타임아웃 | 가정: 30~60초 — 실기 튜닝 필요 |
