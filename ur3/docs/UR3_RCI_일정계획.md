## 3. 일자별 계획

### 8/3 (월) 항목 1. 하드웨어 셋업

RSP4에 OS와 Python3, ur_rtde를 설치하고 이중 네트워크를 구성한 뒤, 그리퍼 캘리브레이션과 카메라 판정 기준까지 마친다.

**오전에 가장 먼저 `ur_rtde` 설치 상태를 확인한다.** wheel이 없어 소스 빌드로 넘어가면 Boost 컴파일에 시간이 크게 소모되므로, 이 시점에 판단해야 남은 반나절을 조정할 수 있다.

*Claude 활용*: `camera_link` 모듈 골격, 그리퍼 매핑표 계산 스크립트. 배선과 캘리브레이션 자체는 직접 해야 한다.

*산출물*: 설정 완료된 RSP4, 그리퍼 신호 매핑표, `camera_link` 모듈

### 8/4 (화) 항목 2. robot_interface

RTDE 수신 스레드, Dashboard TCP 클라이언트, RTDEControl 연결관리를 만든다.

**출력 레시피에 `safety_status_bits`를 넣은 상태로 가장 먼저 연결을 시도한다.** CB3 미지원이면 RTDE 연결 자체가 거부되므로 여기서 즉시 판별되며, 미지원 판명 시 DID 0x010D 사양 변경을 당일에 문서에 반영한다.

*Claude 활용*: 수신 스레드와 캐시 구조, Dashboard 명령 래퍼 12종. 명령별 응답 문자열 판정표는 실기에서 직접 받아 채워야 한다.

*산출물*: `robot_interface` 모듈 3종, Dashboard 명령 판정표, `safety_status_bits` 확인 결과

### 8/5 (수) 항목 3. UDS 처리 구현

mqtt_client, 요청 큐와 우선순위 스케줄러, uds_server 디스패처, 상태 저장소, 설정 JSON 스키마를 만든다.

**웨이포인트 테이블을 여기서 처음 정의한다.** RID 0x0303이 인덱스만 받고 그 좌표가 명세 어디에도 없으므로, 설정 JSON에 등록할 초안을 만든다.

*Claude 활용*: 이 항목이 Claude 효율이 가장 높다. MQTT 클라이언트, 우선순위 큐, 디스패처 라우팅, JSON 영속 계층 모두 정형화된 구조다.

*산출물*: `mqtt_client`, 요청 큐, `uds_server`, 상태 저장소, 설정 JSON 스키마, 웨이포인트 테이블 초안

### 8/6 (목) 항목 4. 세션 / 보안 / 리셋

DiagnosticSessionControl, TesterPresent, SecurityAccess, ECUReset을 구현한다.

**S3 타임아웃 시 일괄 초기화 함수가 네 상태를 모두 되돌리는지 반드시 확인한다.** 나머지 서비스가 전부 이 상태를 전제조건으로 검사하므로, 여기서 누락이 생기면 이후 모든 항목에서 원인 불명의 버그로 나타난다.

*Claude 활용*: 상태 기계와 타이머, Seed/Key 검증 로직, 서브펑션 분기.

*산출물*: `session_mgr`, `security_mgr`, `agent_reset`, S3 타이머, ECUReset 서브펑션 지원 목록

### 8/7 (금) 항목 5. 데이터 읽기 / 쓰기

ReadDataByIdentifier와 WriteDataByIdentifier를 구현한다. DID 20종의 인코딩이 주 작업이다.

**명세 부록의 예시 프레임을 기대값으로 삼아 인코딩을 검증한다.** 음수 각도가 2의 보수로 정확히 나가는지가 가장 틀리기 쉬운 부분이다.

*Claude 활용*: 이 항목도 효율이 높다. DID 매핑 테이블과 단위 변환 함수, 예시 프레임 기반 검증 코드를 한 번에 생성할 수 있다.

*산출물*: `did_read`, `did_write`, DID 매핑 테이블, 인코딩 유틸, 로봇 두절 시 응답 정책 확정안

**1주차 체크포인트**: 8/7 종료 시점에 `22 01 07` 요청이 MQTT로 들어가 `62 01 07 07` 응답이 돌아와야 한다. 이것이 되면 웹앱에서 로봇까지의 경로가 뚫린 것이고, 남은 항목은 이 경로 위에 서비스를 붙이는 작업이 된다. 되지 않으면 8/10에 항목 8을 시작하지 말고 이 경로부터 완성한다.

### 8/10 (월) 항목 8. DTC 읽기/쓰기

DTC 저장소, ReadDTCInformation, ClearDiagnosticInformation, `dtc_monitor`를 구현한다.

**보호정지 발생 시각 기록을 빠뜨리지 않는다.** 8/12의 0x0204 5초 제약 판정이 이 값에 걸려 있다. `safety_mode`가 3으로 전이하는 순간에만 기록해야 하며, 값이 3인 동안 매 주기 갱신하면 안 된다.

*Claude 활용*: 주기 감시 루프와 8종 조건 판정, JSON 저장소.

*산출물*: `dtc_store`, `dtc_monitor`, ReadDTCInformation 응답 포맷 확정안, 과온 임계값 정정

### 8/11 (화) 항목 9. 응답 지연, 에러/상태 발행, 재접속 처리

responsePending 공통 처리기, error 토픽 3종, status 토픽 전이 발행, 상황별 재접속 정책을 구현한다.

이 항목은 상당 부분이 앞선 작업에 이미 들어가 있다. 토픽 발행 함수는 8/5의 `mqtt_client`에, RTDE 5초 재접속과 Dashboard close 확인은 8/4의 `robot_interface`에 있다. **새로 만드는 것은 responsePending 공통 처리기이며, 이것이 다음 날 항목 6의 선행 조건이다.**

*Claude 활용*: 재발행 타이머와 횟수 제한 로직, error/status 페이로드 구성.

*산출물*: responsePending 처리기, error/status 발행 모듈, 재접속 정책 통합

### 8/12 (수) 항목 6. 강제 구동

InputOutputControlByIdentifier 5개 DID와 returnControlToECU를 구현한다.

**0x0201의 재생 절차 순서를 지킨다.** RTDEControlInterface disconnect를 먼저 하고 Dashboard play를 실행하며, 재생 종료는 `runtime_state` 폴링으로 감지해 `reuploadScript()`로 재연결한다. 이 순서가 어긋나면 다음 날 항목 7이 동작하지 않는다.

*Claude 활용*: DID별 핸들러와 전제조건 검사, returnControl 반환 동작 테이블. Dashboard 응답 판정과 실제 로봇 동작 확인은 직접 해야 한다.

*산출물*: `io_control` 모듈, 제어권 관리, DID 0x0205 결번 확정안

### 8/13 (목) 항목 7. 루틴 실행

RoutineControl의 startRoutine, requestRoutineResults, stopRoutine을 구현한다.

**로봇이 실제로 움직이는 날이므로 안전 준비를 먼저 한다.** 로봇 반경 안에 사람과 장애물이 없어야 하고, 티치펜던트 비상정지 버튼에 손이 닿는 위치에서 진행하며, PolyScope Installation의 세이프티 존을 낮게 설정하고, 0x0202 속도 슬라이더를 20~30%로 먼저 낮춘 뒤 시작한다.

**0x0303 웨이포인트 이동부터 확인한다.** 사전정의 좌표라 가장 안전하다. 이후 0x0301, 0x0302 순으로 넘어가고, 각 단계에서 범위 밖 목표값에 `7F 31 31`이 나오고 로봇이 움직이지 않는지 함께 확인한다.

*Claude 활용*: 파라미터 디코딩, 전제조건 검사 순서, 결과 조립. 실행시간 필드 사양과 실패 사유코드 체계는 여기서 확정한다.

*산출물*: `motion_ctrl` 모듈, 웨이포인트 테이블 확정, 실패 사유코드 정의표, 실행시간 필드 사양

### 8/14 (금) 항목 10. 로깅 및 서비스 운영 구성

로깅, systemd 유닛, 설정 외부화, 안전 shutdown을 구현하고 전체를 마무리한다.

**systemd 자동 재시작이 좀비 스크립트 정리와 함께 도는지 확인한다.** 프로세스를 강제 종료한 뒤 자동 재시작되고, 재기동 시 8/4에 만든 헬스체크가 상주 스크립트를 정리해 루틴 실행이 정상 동작하는 것까지가 이 항목의 마지막 확인 사항이다.

*Claude 활용*: 로그 포맷과 회전 설정, systemd 유닛 파일, 시그널 핸들러.

*산출물*: `logger`, systemd 유닛, 설정 파일 스키마, 배포 절차 문서

| R4 | `safety_status_bits`가 CB3 미지원 | DID 0x010D 사양 변경, 문서 3종 수정, 클라우드 공유 | 8/4에 판별하므로 영향 범위가 작다. **이 확인을 뒤로 미루지 않는다.** 미지원이면 안전 모드(0x0108)로 대체하는 것이 이미 정해진 대안이다 |
| R5 | **브로커 접속 정보 미수령** | 8/5 항목 3 착수가 막히고 이후 전부 정지한다 | 클라우드 담당에게 8/4까지 전달을 요청한다(요청서 §9 액션 1). 지연되면 로컬 Mosquitto로 개발하고 나중에 접속 정보만 교체한다 |
| R6 | 실기 UR3 점유 경합 | 실기 확인이 필요한 날의 작업이 밀린다 | 8/3, 8/4, 8/12, 8/13에 로봇이 필요하다. 해당 일자를 미리 확보한다. 특히 8/13은 로봇을 실제로 움직이므로 주변 정리까지 필요하다 |
| R7 | 검증 단계가 일정에 없다 | 구현은 끝났는데 전수 검증이 안 된 상태로 8/14를 맞는다 | 각 항목의 완료 기준에 자체 동작 확인이 포함되어 있다. 다만 프로토콜 단위 테스트 전수, 실기 구동 검증, 클라우드 연동 검증은 별도 단계이므로 **8/17 이후로 편성해야 한다.** 8/14는 구현 완료 시점이지 검증 완료 시점이 아니다 |

## 6. 8/14 이후로 넘어가는 작업

본 일정은 구현만 다룬다. 아래는 별도 단계로 편성이 필요하다.

| 작업 | 내용 |
|---|---|
| 프로토콜 단위 테스트 | `robot_interface` 스텁 기반으로 인코딩, NRC 분기 전수, 상태 기계 전이를 로봇 없이 검증 |
| 실기 구동 검증 | 0x2F 5개 DID와 0x31 3개 RID의 실동작 확인, stopRoutine 응답시간 측정, DTC 임계값과 런어웨이 타임아웃 실측 확정 |
| 클라우드 연동 검증 | 웹앱에서 로봇까지 전 구간 확인, 구현 중 확정한 항목의 상호 확인, QoS1 중복 수신, 폴링 주기 합의, 비상정지 버튼 응답시간 |
| 이상 복구 검증 | RTDE 두절, Dashboard 소켓 끊김, 보호정지 복구, LWT와 좀비 스크립트 정리, 모션 중 S3 타임아웃 |
| RID 0x0304 이미지 캡처 | 클라우드 담당과 이미지 전달 채널 합의 후 착수 |
